# Upgrading to 0.90

0.90 is a correctness release. Most breaking changes are refusals: a shape that returned wrong rows now throws a typed error naming the fix, so your tests find it. A smaller set changes results without an error. Those come first; read them even if your tests pass.

## Before you start

- **Regenerate, then type-check.** Run `turbine generate`, then `tsc --noEmit`. The [stricter types](#generated-types) and [`col()`](#filters-and-operands) show up as compile errors.
- **Run your tests outside production mode.** Some checks are development-mode advice ([Logging](#logging-and-diagnostics)).
- **Know the codes.** A refusal is `ValidationError` (`TURBINE_E003`), an engine gap `UnsupportedFeatureError` (`TURBINE_E017`), a connection problem `ConnectionError` (`TURBINE_E004`).
- **Check stored data** for [SQLite `date` values](#engines) and [JSON arrays stored as `{}`](#json), and [`defineSchema` keys](#schema-and-custom-dialects) that changed your DDL.

## Results that change without an error

### JSON

<a id="pathless-json-equals-compares-the-whole-document" />

- **A pathless `equals` on a JSON column is exact document equality.** It used to mean containment (`@>`). **Do:** use `contains` where you meant containment.

  ```ts
  // Stored: { plan: 'pro' } and { plan: 'pro', seats: 5 }
  await db.accounts.findMany({ where: { meta: { equals: { plan: 'pro' } } } });   // 0.90: only the first
  await db.accounts.findMany({ where: { meta: { contains: { plan: 'pro' } } } }); // both
  ```

  `not: <document>` now means "not this exact document"; write `NOT: { meta: { contains: ... } }` for "does not contain". SQL Server and SQLite refuse a pathless `equals` (`TURBINE_E017`).
- **A path `equals` compares JSON values.** `equals: 5` no longer matches the string `"5"`, and `equals: null` matches a stored JSON `null`. **Do:** pass the JSON type you stored.
- **JSON arrays are stored as arrays.** They used to be sent as Postgres array literals, so `[]` stored `{}`. **Do:** check old rows with `jsonb_typeof(col)`. Use `jsonValue()` to store a JSON string or JSON `null`.
- **In `update` data, `{ increment: 1 }` on a JSON column is stored as that document.** Only `{ set }` is unwrapped.
- **On MySQL, SQLite and SQL Server, a JSON path key with a backslash, quote or newline finds its value.**

### Filters

- **`OR: []` matches no row**, as in Prisma. It used to match every row. **Do:** leave `OR` out when the list can be empty.

  ```ts
  await db.users.findMany({ where: picked.length ? { OR: picked } : {} });
  ```

- **An `OR` branch with no condition (`{}`) makes the `OR` match every row.** It used to be dropped. **Do:** filter empty branches out.
- **`not: { lt: 4 }` compiles to `NOT ("score" < $1)`.** It used to compare against the object and match nearly every row.
- **In `having`, `NOT: [a, b]` means `NOT a AND NOT b`**, as in `where`. Write `NOT: { AND: [a, b] }` for the old meaning.
- **`globalFilters` keyed by the client accessor apply.** A key like `blogPosts` (table `blog_posts`) used to filter nothing.
- **On MySQL, a number compared with a text column binds as text.** `{ resetToken: 0 }` used to match every token not starting with a digit. **Do:** pass `'0'`.

### Pagination and ordering

<a id="a-cursor-page-is-always-ordered" />

- **A cursor page is always ordered.** Turbine appends the primary key to `orderBy` unless the order already contains a unique NOT NULL key, and orders by the primary key when there is no `orderBy`.

  ```ts
  await db.posts.findMany({ cursor: { id: 40 }, limit: 20 });
  // 0.81: WHERE "id" > $1 LIMIT $2
  // 0.90: WHERE "id" > $1 ORDER BY "id" ASC LIMIT $2
  ```

- **A paginated `findMany` gets the same tiebreaker**, as does `findFirst` with `offset`. **Do:** check `explain()` on sorts over low-cardinality columns; an index on `(sort column, id)` covers the new order.
- **Streams honour `limit`, `take` and `offset`, and `with` honours `take`, `skip` and `offset`.** `offset` on a to-one relation throws.

### Reads

- **`turbine generate` applies `pii`, `updatedAt` and `maxLength` from your schema file**, so PII columns leave default reads and `update` stamps `updatedAt`. **Do:** read PII with [`includePii: UNSAFE`](#a-pii-column-in-select-needs-includepii-unsafe).
- **Enum arrays read as arrays** at the top level too. Remove code that parses `{draft,live}`.
- **`NotFoundError.where` is not enumerable in safe mode.** Read `err.where` directly.

### Writes and transactions

- **A timed-out query is cancelled on the server** (PostgreSQL). `TimeoutError.outcome` is `'not-executed'` (safe to retry) or `'unknown'`. **Do:** retry writes only on `'not-executed'`. See [Per-query timeout](/client#per-query-timeout).
- **`upsert` stamps `updatedAt` on its single-statement path too.**
- **Nested writes and lookup-first upserts run in their own savepoint** inside `$transaction`, so a caught failure leaves nothing half done. A writing `pipeline()` rolls back entirely when a `findUniqueOrThrow` misses.
- **`$transaction([...], options)` applies `isolationLevel`, `sessionContext` and `timeout`.**
- **`belongsTo` nested writes follow to-one rules:**

  | Shape | 0.81 | 0.90 |
  |---|---|---|
  | `delete: true` | did nothing | clears the foreign key and deletes the row |
  | `disconnect: false` | disconnected | does nothing |
  | `disconnect: { id }` | disconnected unchecked | must match, else `NotFoundError` |
  | `connectOrCreate` in `update` | ignored | runs |
  | `set`, two operations, several items | accepted | `TURBINE_E003` |

### Engines

- **Values match PostgreSQL.** Remove workarounds for the old ones:
  - SQLite: `boolean` and `json` columns decode (Node 22.16+ or 23.11+), and integer `divide` truncates.
  - SQL Server: a `Date` keeps its milliseconds, `json` reads parsed, and `_avg` over an integer is fractional.
  - MySQL: integer `_avg` keeps full precision, integer `divide` truncates, and `in` / `notIn` match what `equals` matches.
- **A `Date` on a `date` column binds its UTC day on every engine.** **Do (SQLite):** rewrite older rows once:

  ```sql
  UPDATE events SET run_on = substr(run_on, 1, 10) WHERE length(run_on) > 10;
  ```

- **MySQL `update`, `delete` and `upsert` write and read back in one transaction**, and target the row `where` names. A pool without `connect()` cannot run them.
- **MySQL LIKE filters escape with `!`**, so they work in any `sql_mode`.
- **SQLite: a statement from outside an open `$transaction` waits** up to `busyTimeoutMs`.
- **PowDB: global filters apply on every relation load path.** `is` / `isNot` filter (they matched every row), `none` and `every` follow SQL `NULL` semantics, and bigint `_sum` returns decimal text.

## Shapes that now throw

### Filters and operands

- **Column references use `col()`.** A plain `{ col: 'x' }` is what `JSON.parse` makes from a request body, so it is now a value.

  ```ts
  import { col } from 'turbine-orm';

  where: { currentVersionId: { not: col('publishedVersionId') } } // was { col: '...' }
  ```

- **An operand must fit its column.** An object or array at a scalar position, `gt: null`, a non-array `in` or an unknown `mode` throws. Use `{ in: [...] }` or `equals: null`.
- **Unreadable filter shapes throw:** `OR: { ... }` (wrap it in an array), `some: null` (write `some: {}`), `is` on a to-many relation, an operator object with no operator, an Invalid Date, and an empty `groupBy` `by`.
- **A mutation refuses an always-true `where`**, such as `{ id: { notIn: [] } }` or `contains: ''` on a NOT NULL column. Guard the empty list, or pass `allowFullTableScan: UNSAFE`.
- **`findFirst` refuses a `where` whose every key is `undefined`.** Omit `where` to ask for any row.
- **One-row lookups (`findUnique`, `update`, `delete`, `upsert`) take a plain value or `{ equals }` on the key.** Use `findFirst` for `mode: 'insensitive'` or ranges.

### PII and global filters

<a id="a-pii-column-in-select-needs-includepii-unsafe" />

- **A PII column in `select` needs `includePii: UNSAFE`**, at every `with` depth. `select` often comes from request data, so naming the column is no longer the opt-in.

  ```ts
  import { UNSAFE } from 'turbine-orm';

  await db.users.findMany({ select: { id: true, email: true }, includePii: UNSAFE });
  ```

  A write `select` naming a PII column throws. `omit`, `where` and `orderBy` are unchanged.
- **A function filter that returns `undefined` throws** instead of filtering nothing. Return `null` or `{}` for "no filter".
- **Static global filters are compiled at construction**, so a bad operand, an unknown key or a filter cycle fails the constructor.

### Pagination

- **A cursor must place the page:** a value for every `orderBy` column plus the tiebreaker, or a unique key. `cursor: null` and `cursor: {}` throw; leave `cursor` out on the first page.

  ```ts
  await db.posts.findMany({ orderBy: { createdAt: 'desc' }, cursor: { id: last.id }, limit: 20 });
  ```

- **`updateMany` and `deleteMany` refuse `limit`, `take`, `offset` and `skip`.** They were ignored. Select the ids, then write by `id: { in: ids }`.

### Writes

- **`optimisticLock` works on `update` only.** Elsewhere it was ignored. Put the version in `where` (`{ id, version: expected }`) instead.
- **An object or array written to a scalar column throws**, and so does a `Map` or `Set` anywhere. SQLite and SQL Server text columns still take an object as JSON text. `JSON.stringify` it first.
- **An atomic operator in `create` data throws.**
- **`buildCreateMany` past the bind-parameter limit throws.** `createMany()` chunks for you; split rows yourself before a `pipeline`.

### Options and middleware

- **Middleware cannot change the arguments.** `next()` throws a `TypeError` naming the changed path. Put the condition in the query, or use [`globalFilters`](/global-filters).
- **A string or negative `timeout`, or an unknown `relationLoadStrategy`, throws.** Wrap configured values in `Number(...)`; `timeout: 0` still means none.

### Schema and custom dialects

- **`defineSchema` refuses unknown keys**, unresolvable `references` and index columns, and two fields mapping to one column. A misspelt key used to change your DDL silently, so review `turbine push --dry-run` after fixing it.
- **A hand-built `Dialect` needs `capabilities`.** A dialect spread from `postgresDialect` inherits PostgreSQL's answers, so state your engine's values. See [Dialects](/dialects#engine-capabilities-what-the-engine-is-not-what-it-is-called).

  ```ts
  import { postgresDialect, type Dialect } from 'turbine-orm';

  export const myDialect: Dialect = {
    ...postgresDialect,
    name: 'myengine',
    capabilities: { ...postgresDialect.capabilities, distinctOn: false, positionalJson: false },
  };
  ```

- **`postgresDialect.introspector` is removed.** Call `introspect({ connectionString })`.

### Error classes that changed

| Situation | Now |
|---|---|
| A write in a read-only transaction | `ReadOnlyError` (`TURBINE_E018`), `reason: 'transaction'` |
| A value the server cannot read as the column type | `ValidationError` (`TURBINE_E003`), was `ConnectionError` |
| PostgreSQL `42883` (no operator for these types) | `ValidationError` (`TURBINE_E003`) |
| A malformed `defineSchema` declaration | `ValidationError` (`TURBINE_E003`), was `Error` |
| An exhausted pool | `ConnectionError` (`TURBINE_E004`), was pg-pool's `Error` |
| A lock wait timeout (MySQL 1205, SQL Server 1222) | `LockNotAvailableError` (`TURBINE_E013`, still retryable) |
| A transaction PostgreSQL rolled back on `COMMIT` | `TransactionRolledBackError` (`TURBINE_E019`), new |
| A failed internal self-check | [`InvariantError`](/errors#e020) (`TURBINE_E020`), new; report it |

### Transactions

- **A rolled-back transaction rejects.** If your callback catches a failed statement, PostgreSQL rolls back on `COMMIT` and `$transaction` rejects with `TransactionRolledBackError`. Recover expected failures in a nested block:

  ```ts
  import { UniqueConstraintError } from 'turbine-orm';

  await db.$transaction(async (tx) => {
    try {
      await tx.$transaction((inner) => inner.users.create({ data: { email } }));
    } catch (err) {
      if (!(err instanceof UniqueConstraintError)) throw err;
    }
  });
  ```

- **On PostgreSQL, the statement after a failed one is refused.**
- **A nested block has its own handle.** Using the outer `tx` while it is open throws.
- **Transaction-control SQL through `tx.raw` or `tx.$connection()` throws.** Return to commit, throw to roll back, nest for a savepoint.
- **A settled `tx` throws, and a callback that returns with queries still running rolls back.** Await every query.
- **A per-query timeout inside `$transaction` rolls it back.** Retry the whole transaction.
- **`sessionContext` names need a dot** (`app.tenant`) unless listed in `allowBuiltinSettings`; values must be strings, numbers or booleans.
- **A Promise in `$transaction([...])` or `pipeline([...])` throws.** Pass `build*()` results.

### Connections

- **A stream idle for five minutes is closed.** Set `idleTimeoutMs` per call or `streamIdleTimeoutMs: 0`. See [Abandoned streams](/queries#abandoned-streams-close-themselves).
- **A client with no database configured rejects its first query.** Turbine does not read `.env`; use `node --env-file=.env`.
- **A pooler URL defaults to `preparedStatements: false`.** Set `true` if your pooler tracks prepared statements.
- **Owned pools retire connections after 30 minutes** (`maxLifetimeSeconds: 0` keeps them).
- **A pool without `connect()` throws `TURBINE_E017`** for transactions, cursor streams and chunked `createMany`.
- **`db.raw` and `db.sql` take only a tagged template.** Use `db.rawUnsafe(text, ...values)`.
- **`PGHOST`, `PGPORT`, `PGDATABASE` and `PGUSER` are honoured.** Set `user` if you relied on the `postgres` default.

### prisma-compat

- `take`, `skip` and `cursor` on `count` and `aggregate`, a nested `cursor` or `distinct`, and a filtered relation `_count` throw `TURBINE_E017`.
- An untranslated option throws `TURBINE_E003` instead of being ignored. See [what it translates](/migrate-from-prisma).
- `count({ select })` returns Prisma's per-field object, and cursors start at the cursor row as in Prisma.

### Engine refusals

- **SQLite:** calling `db` (not `tx`) inside its own `$transaction` throws, and `SQLITE_BUSY` is a retryable `SerializationFailureError`.
- **SQLite, MySQL, SQL Server:** `rawUnsafe` placeholders are `$1`, `$2`; `?` throws.
- **MySQL:** `NaN` and Invalid Dates throw. A `create` whose new key the server cannot report (a UUID default) throws; pass the key in `data`.
- **SQL Server:** a binary value in an `in` list throws; write `OR` branches.
- **PowDB:** `pipeline()` and `$transaction([...])` throw; run batches in `db.$transaction(async (tx) => ...)`. See [PowDB](/powdb).

## Logging and diagnostics

- **[`diagnostics`](/observability#diagnostics-diagnostics) reads `NODE_ENV` once, at construction.** A runtime with a `process` but no `NODE_ENV` defaults to development; set `diagnostics: 'production'` there.
- **Construction warnings fire in every mode** (unknown config keys, prepared statements on a pooler). Route them with [`logger`](/observability#log-output-logger); `logger: {}` silences Turbine.
- **Every log line carries a stable `code`.** Match on it, not on the text.

## Tooling

### `turbine generate`

- **It loads `turbine/schema.ts`**, so it needs `tsx` when that file exists.
- **A `tsType` or `columnTypes` value must be one TypeScript type on one line.** Use `import('./x.js').T` for anything longer.
- **A declared `tsType` no longer changes runtime metadata.** Read it from `declaredTsType`.

### Generated types

Compile-time only:

- `create` requires every NOT NULL column without a default.
- `findUnique`, `upsert` and nested `connect` take a unique key.
- A loaded `belongsTo` with a NOT NULL foreign key is non-null, unless its `with` has a `where`.
- `_count: true` is typed per relation (`{ posts: number }`).
- `interval` is an object, `point` is `{ x, y }`, `bigint[]` is `string[]`.

### Migrations

- **`migrate create --auto` refuses while migrations are pending** (`--allow-pending` overrides), and `migrate create` never overwrites a file.
- **Filenames are stamped in UTC.**
- **`migrate up`, `deploy` and `down` refuse a pooler URL.** Use the direct endpoint, or `--allow-pooler`.
- **Lossless widenings are no longer destructive**, and `migrate up`, `down` and `push` also stop on a constant-true `UPDATE`, an unrestricted `ON CONFLICT DO UPDATE` and `DROP VIEW ... CASCADE`. See [drift in CI](/migrate#checking-for-drift-in-ci) for the new `--exit-code` flags.

### DDL for MySQL, SQLite and SQL Server

`schemaToSQL` now keeps each dialect's type mapping: auto-increment keys, `VARCHAR` lengths, MySQL `DATETIME(3)` and table-level foreign keys, SQL Server `DATETIMEOFFSET`, and enum columns on every engine. Regenerate the DDL and review it before applying it to an existing database.

### Studio, Observe and MCP

- The printed URL carries a one-time ticket, exchanged for a cookie on first visit.
- The MCP server also hides camelCase secret names (`apiKey`, `accessToken`).
