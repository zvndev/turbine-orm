# Vector Search (pgvector)

Rank rows by similarity to a query vector without writing raw SQL, for semantic search, recommendations or RAG retrieval. Turbine queries [pgvector](https://github.com/pgvector/pgvector) columns through the same `findMany` you already use: `orderBy` ranks nearest neighbors and `where` applies distance thresholds.

You need the `pgvector` extension and a `vector` column on your table.

## KNN, order by distance

Put a `distance` object on a `vector` column in `orderBy` to sort rows by distance to a query vector. Add `limit` to take the closest *k*.

```ts
const similar = await db.items.findMany({
  orderBy: { embedding: { distance: { to: queryVector, metric: 'cosine' } } },
  limit: 5,
});
// queryVector is a number[]; the 5 nearest rows, nearest-first
```

`to` is a `number[]`. The default direction is `'asc'`: smallest distance, so nearest, first. Pass `direction: 'desc'` to invert it:

```ts
const farthest = await db.items.findMany({
  orderBy: { embedding: { distance: { to: queryVector, metric: 'cosine', direction: 'desc' } } },
  limit: 5,
});
```

The first query compiles to `ORDER BY "embedding" <=> $1::vector ASC`, with the vector bound as a parameter.

## Distance filter, keep rows within a threshold

Put the same `distance` object in `where`, with a comparator, to keep only rows inside or outside a distance threshold.

```ts
const close = await db.items.findMany({
  where: { embedding: { distance: { to: queryVector, metric: 'l2', lt: 0.3 } } },
});
// Generates: WHERE "embedding" <-> $1::vector < $2
```

Distance filters accept `lt`, `lte`, `gt` and `gte`. A filter with no comparator throws `ValidationError`.

Combine a filter with KNN ordering to get the closest matches that clear a quality bar:

```ts
const results = await db.items.findMany({
  where: { embedding: { distance: { to: queryVector, metric: 'cosine', lt: 0.4 } } },
  orderBy: { embedding: { distance: { to: queryVector, metric: 'cosine' } } },
  limit: 10,
});
```

## Metrics

`metric` selects the pgvector distance operator:

| `metric` | Operator | Distance |
|---|---|---|
| `'l2'` | `<->` | Euclidean (L2) distance |
| `'cosine'` | `<=>` | Cosine distance |
| `'ip'` | `<#>` | Negative inner product |

An unknown metric throws `ValidationError`, and so does a `distance` operator on a column that is not a `vector`.

> **Note:** `pg` has no built-in parser for the `vector` type, so a selected `vector` column comes back as a string such as `'[1,2,3]'` unless you register a parser, for example with pgvector's client helpers. This only affects how the column reads; querying *by* distance works either way.

## The exported types

Every vector type is exported from the package root, so you can build a query object in a helper and pass it to `findMany` without losing type safety.

```ts
import type {
  VectorMetric,
  VectorFilter,
  VectorDistanceFilter,
  VectorOrderBy,
  VectorOrderByDistance,
} from 'turbine-orm';
```

| Type | Shape | Where it goes |
|---|---|---|
| `VectorMetric` | `'l2' \| 'cosine' \| 'ip'` | The `metric` field of both specs below. It is a fixed allow-list, so a user-supplied string never becomes a SQL operator. |
| `VectorDistanceFilter` | `{ to: number[]; metric: VectorMetric; lt?, lte?, gt?, gte?: number }` | The `distance` value inside a `where`. |
| `VectorFilter` | `{ distance: VectorDistanceFilter }` | The per-column value in `where`, i.e. `where: { embedding: VectorFilter }`. |
| `VectorOrderByDistance` | `{ to: number[]; metric: VectorMetric; direction?: 'asc' \| 'desc' }` | The `distance` value inside an `orderBy`. `direction` defaults to `'asc'`, which is nearest-first. |
| `VectorOrderBy` | `{ distance: VectorOrderByDistance }` | The per-column value in `orderBy`, i.e. `orderBy: { embedding: VectorOrderBy }`. |

A typical use is a retrieval helper that takes the query embedding once and builds both halves:

```ts
import type { VectorFilter, VectorMetric, VectorOrderBy } from 'turbine-orm';

function knn(to: number[], metric: VectorMetric = 'cosine', maxDistance?: number) {
  const order: VectorOrderBy = { distance: { to, metric } };
  const filter: VectorFilter | undefined =
    maxDistance === undefined ? undefined : { distance: { to, metric, lt: maxDistance } };
  return { order, filter };
}

const { order, filter } = knn(queryVector, 'cosine', 0.4);

const results = await db.items.findMany({
  where: filter ? { embedding: filter } : undefined,
  orderBy: { embedding: order },
  limit: 10,
});
```

<Callout type="note" title="Postgres only">
  The vector operators depend on the dialect's `supportsVector` capability
  flag. On the SQLite, MySQL, SQL Server and PowDB engines, a `distance` filter
  or ordering throws `UnsupportedFeatureError` (`TURBINE_E017`) instead of
  emitting SQL that cannot run.
</Callout>

## Validation and safety

Every value in a vector query is bound as a parameter, so hostile input cannot escape the query:

- The query vector is bound as `$n::vector`.
- Each distance threshold is bound as `$n`.
- An empty `to`, an element of `to` that is not a finite number (`NaN` and `Infinity` included), or a threshold that is not a finite number throws `ValidationError` before any query runs.

## The same query, three ways

The task: the 10 nearest rows by cosine distance, filtered to a quality threshold, fully parameterized.

**Turbine**: `distance` is a `where` / `orderBy` operator on `vector` columns.

```ts
const results = await db.items.findMany({
  where: { embedding: { distance: { to: queryVector, metric: 'cosine', lt: 0.4 } } },
  orderBy: { embedding: { distance: { to: queryVector, metric: 'cosine' } } },
  limit: 10,
});
```

**Prisma**: pgvector columns are `Unsupported("vector")` in the schema, so querying by distance means `$queryRaw`, with the vector serialized to a string and cast by hand.

```ts
const embedding = `[${queryVector.join(',')}]`;

const results = await prisma.$queryRaw<
  { id: number; title: string; distance: number }[]
>`
  SELECT id, title, embedding <=> ${embedding}::vector AS distance
  FROM items
  WHERE embedding <=> ${embedding}::vector < 0.4
  ORDER BY distance
  LIMIT 10
`;
```

**Drizzle**: a native `vector` column type plus SQL expression helpers. You build the distance expression with `cosineDistance` and pass it to `where` and `orderBy`.

```ts
import { asc, cosineDistance, lt } from 'drizzle-orm';

const distance = cosineDistance(items.embedding, queryVector);

const results = await db
  .select({ id: items.id, title: items.title, distance })
  .from(items)
  .where(lt(distance, 0.4))
  .orderBy(asc(distance))
  .limit(10);
```

All three run the same SQL. They differ in where the vector logic lives: in Turbine it is part of the typed query object, in Prisma it is raw SQL you maintain, and in Drizzle it is SQL expression helpers you compose.
