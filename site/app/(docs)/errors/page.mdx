# Typed Errors

Every error Turbine throws extends `TurbineError` and carries a stable `code`, such as `TURBINE_E008`. Branch on `err.code` or `instanceof`, never on the message text.

```ts
import { NotFoundError, UniqueConstraintError } from 'turbine-orm';

try {
  await db.users.create({ data: { email: 'taken@example.com' } });
} catch (err) {
  if (err instanceof UniqueConstraintError) return { status: 409 }; // err.columns: ['email']
  if (err instanceof NotFoundError) return { status: 404 };
  throw err;
}
```

- Each message starts with its code (`[TURBINE_E008] ...`) and ends with a link to its entry below, which `err.docsUrl` also holds.
- `instanceof` works even when a process loads the package twice, as ESM and as CommonJS. `err.code` needs no import, so it suits shared handlers.
- A database error with a known SQLSTATE becomes one of these classes, with the driver's error as `.cause`. Any other keeps the driver's class: see [Unmapped SQLSTATEs](#unmapped-sqlstates).

## Error code table

| Code | Class | When | What to do |
|---|---|---|---|
| [`TURBINE_E001`](#e001) | `NotFoundError` | An `...OrThrow` read, update or delete matched no row | Return a 404, or use the non-throwing method |
| [`TURBINE_E002`](#e002) | `TimeoutError` | A query or transaction ran past its timeout | Retry only when `outcome` is `'not-executed'` |
| [`TURBINE_E003`](#e003) | `ValidationError` | The call is invalid | Fix the call; the message names the field |
| [`TURBINE_E004`](#e004) | `ConnectionError` | No connection, a lost connection, or a pooler mismatch | Check the URL, server and pool size |
| [`TURBINE_E005`](#e005) | `RelationError` | Unknown relation in `with` | Use the name from the generated types |
| [`TURBINE_E006`](#e006) | `MigrationError` | Checksum mismatch, lock held, or a migration failed | Reconcile the file, or wait for the other run |
| [`TURBINE_E007`](#e007) | `CircularRelationError` | `with` nested deeper than 10 | Split the read |
| [`TURBINE_E008`](#e008) | `UniqueConstraintError` | Duplicate key (`23505`) | Report a conflict, or use `upsert` |
| [`TURBINE_E009`](#e009) | `ForeignKeyError` | Missing or still-referenced parent row (`23503`) | Write the parent first, or delete children first |
| [`TURBINE_E010`](#e010) | `NotNullViolationError` | A required column got no value (`23502`) | Supply the value, or give the column a default |
| [`TURBINE_E011`](#e011) | `CheckConstraintError` | A `CHECK` constraint rejected the row (`23514`) | Fix the value |
| [`TURBINE_E012`](#e012) | `DeadlockError` | Deadlock (`40P01`) | Retry with `withRetry` |
| [`TURBINE_E013`](#e013) | `SerializationFailureError` | Serialization conflict or unavailable lock | Retry with `withRetry` |
| [`TURBINE_E014`](#e014) | `PipelineError` | A non-transactional pipeline had failures | Read `err.results` |
| [`TURBINE_E015`](#e015) | `OptimisticLockError` | The row's version changed since you read it | Re-read and retry, or report the conflict |
| [`TURBINE_E016`](#e016) | `ExclusionConstraintError` | An exclusion constraint rejected the row (`23P01`) | Fix the overlapping value |
| [`TURBINE_E017`](#e017) | `UnsupportedFeatureError` | This engine or path cannot do that | Read `err.feature`; use the supported path |
| [`TURBINE_E018`](#e018) | `ReadOnlyError` | A write hit a read-only database, role or transaction | Route the write to the primary |
| [`TURBINE_E019`](#e019) | `TransactionRolledBackError` | A failed statement rolled the transaction back | Read `cause`; isolate expected failures in a nested block |
| [`TURBINE_E020`](#e020) | `InvariantError` | Turbine caught a bug in itself | Report it |

## Error reference

<a id="e001" />
### E001 `NotFoundError`

`findUniqueOrThrow` or `findFirstOrThrow` found nothing, or an `update` or `delete` matched no row. It carries `table`, `where` and `operation`. In the default safe mode, the message names only the `where` keys (see [Safe error messages](#safe-error-messages)).

<a id="e002" />
### E002 `TimeoutError`

A query or transaction ran past its `timeout`, or the server's `statement_timeout` cancelled it (`57014`). It carries `timeoutMs` and `outcome`:

- `'not-executed'`: the statement made no change, so a retry is safe.
- `'unknown'`: it may have committed. Check before retrying a write.

The next pull on a cursor stream that was closed after its [idle timeout](/queries#abandoned-streams-close-themselves) also throws it, with `'not-executed'`. See [per-query timeout](/queries#per-query-timeout).

<a id="e003" />
### E003 `ValidationError`

The call is invalid, so the statement did not run or the database rejected a value. Common causes:

- **Names**: an unknown column or key anywhere in the call (see [Unknown field names](#unknown-field-names)), a `defineSchema` reference it cannot resolve, a `globalFilters` key that names nothing.
- **Values**: an operand that does not fit its operator or column, an Invalid Date, an object written to a scalar column, a value the database cannot read as the column's type (class `22`, `42883`).
- **Where clauses**: an `update` / `delete` with an empty `where`, or one that is always true (`NOT: { OR: [] }`, `notIn: []`), and a relation filter whose value is not a where object.
- **Options**: a [privilege option](/global-filters#privilege-options-and-the-unsafe-symbol) set to `true` instead of `UNSAFE`, a PII column in `select` or an aggregate without `includePii: UNSAFE`, an invalid `cursor`, `timeout` or `relationLoadStrategy`, `optimisticLock` on `upsert`, `updateMany`, `delete` or `deleteMany`, and a `lock` outside a transaction.
- **Transactions**: a query on a `tx` whose transaction has finished, a callback that returned while its query was still running, and `BEGIN`, `COMMIT` or `ROLLBACK` sent through raw SQL inside a transaction.
- **Setup and engines**: a global filter that does not compile, a malformed client option, a MySQL `in` list past 65,535 placeholders, a non-numeric string written to a numeric column on SQLite.

It may carry `column`, `sqlstate` and, in verbose mode, `detail`.

### Unknown field names

Every name you pass is checked against the schema in `where`, `orderBy`, `distinct`, `groupBy`, aggregates, `data`, `select` and `omit`, at every depth. An unknown name throws E003 with the closest match; it is never dropped. A relation named in `select` gets its own message:

```
[TURBINE_E003] "comments" is a relation on table "post", not a column, so it
cannot be named in `select`. Load it with `with: { comments: true }`, which is
a sibling of `select`, not a member of it.
```

To narrow a relation's columns, put `select` inside its options: `with: { comments: { select: { body: true } } }`.

<a id="e004" />
### E004 `ConnectionError`

A connection could not be opened, the server closed one (restart, failover, idle timeout), none came free within `connectionTimeoutMs`, or the client has no database configured. A read outside a transaction is retried once; see [lost connections](/transactions#lost-connections).

Behind a transaction pooler, sqlstates `42P05` and `26000` mean a named prepared statement reached the wrong server connection. Use the direct endpoint, `preparedStatements: false`, or a pooler that tracks prepared statements. It carries `sqlstate`.

<a id="e005" />
### E005 `RelationError`

A `with` clause named a relation the table does not have. The message suggests the closest name. Relation names are in the generated types, or renamed with [`relationNames`](/cli#renaming-derived-relations-relationnames).

<a id="e006" />
### E006 `MigrationError`

A migration file changed after it was applied, another run holds the migration lock, or a migration failed. Reconcile the edited file, wait for the other run (`migrate deploy --wait`), or fix the SQL. See the [CLI](/cli#turbine-migrate-deploy).

<a id="e007" />
### E007 `CircularRelationError`

A `with` tree is nested deeper than 10 levels. `err.path` lists the relations. Split the read into two queries.

<a id="e008" />
### E008 `UniqueConstraintError`

A unique constraint rejected the write (`23505`). It carries `constraint`, `columns` and `table`.

<a id="e009" />
### E009 `ForeignKeyError`

A foreign key rejected the write (`23503`): the referenced row does not exist, or a deleted row is still referenced. It carries `constraint` and `table`.

<a id="e010" />
### E010 `NotNullViolationError`

A `NOT NULL` column got no value (`23502`). It carries `column` and `table`.

<a id="e011" />
### E011 `CheckConstraintError`

A `CHECK` constraint rejected the row (`23514`). It carries `constraint` and `table`.

<a id="e012" />
### E012 `DeadlockError`

The database broke a deadlock by failing this transaction (`40P01`). It has `isRetryable: true`; see [Retryable errors](#retryable-errors).

<a id="e013" />
### E013 `SerializationFailureError`

A serializable or repeatable-read transaction conflicted with another (`40001`), or SQLite reported `SQLITE_BUSY` / `SQLITE_LOCKED`. It has `isRetryable: true`.

Its subclass `LockNotAvailableError` (same code, also retryable) is a [row lock](/queries#row-locks) that could not be taken: PostgreSQL `55P03`, MySQL 3572 and 1205, SQL Server 1222. On PostgreSQL it aborts the transaction, so take the lock inside a nested `tx.$transaction` if you want to recover.

<a id="e014" />
### E014 `PipelineError`

A pipeline run with `{ transactional: false }` had one or more failures. A transactional pipeline (the default) rolls back and throws the failing query's own error instead.

```ts
import { PipelineError } from 'turbine-orm';

try {
  await db.pipeline(queries, { transactional: false });
} catch (err) {
  if (err instanceof PipelineError) {
    // err.results: ({ status: 'ok', value } | { status: 'error', error })[]
    // err.failedIndex, err.failedTag: the first failure
  }
}
```

<a id="e015" />
### E015 `OptimisticLockError`

An `optimisticLock` update found a different version than expected: another write changed the row. It carries `table`, `versionField` and `expectedVersion`. Re-read the row and retry, or report the conflict.

<a id="e016" />
### E016 `ExclusionConstraintError`

An exclusion constraint rejected the row (`23P01`), usually an overlapping range. It carries `constraint` and `table`.

<a id="e017" />
### E017 `UnsupportedFeatureError`

Turbine cannot do this here, so it refuses instead of sending broken SQL. It carries `feature` and `dialect`. Common causes:

- A PostgreSQL-only feature on another [engine](/engines): pgvector operators, `$listen` / `$notify`, RLS `sessionContext`.
- A PowDB feature the connected version is too old for. The message names the minimum version.
- `relationLoadStrategy: 'batched'` on a composite-key relation. Use the default plan.
- A Prisma shape [prisma-compat](/migrate-from-prisma) cannot translate exactly, such as a negative `take` or a `query` extension.

<a id="e018" />
### E018 `ReadOnlyError`

A write was refused as read-only. `err.reason` says why: `'snapshot'`, `'rbac'` or `'transaction'`. See [Read-only refusals](#read-only-refusals).

<a id="e019" />
### E019 `TransactionRolledBackError`

PostgreSQL rolled the transaction back instead of committing, because a statement inside it failed, even if your callback caught the error. The first failure is `cause`. A deadlock, serialization failure or unavailable lock keeps its own retryable class instead. To survive an expected failure, run that statement in a nested block: see [a caught error still rolls the transaction back](/transactions#a-caught-error-still-rolls-the-transaction-back).

<a id="e020" />
### E020 `InvariantError`

Turbine caught a bug in itself before sending a statement it knew was wrong. `err.invariant` names the broken rule. It is not caused by your arguments and is not retryable. Report it at https://github.com/zvndev/turbine-orm/issues with the message, which contains no row or parameter values.

## Retryable errors

`DeadlockError` and `SerializationFailureError` (with `LockNotAvailableError`) have `isRetryable: true`. `withRetry`, also available as `db.$retry`, retries a function on those errors and rethrows anything else:

```ts
import { withRetry } from 'turbine-orm';

await withRetry(() =>
  db.$transaction(
    async (tx) => {
      const row = await tx.counters.findUniqueOrThrow({ where: { id: 1 } });
      await tx.counters.update({
        where: { id: 1 },
        data: { value: row.value + 1 },
      });
    },
    { isolationLevel: 'Serializable' },
  ),
);
```

| Option | Default | |
|---|---|---|
| `maxAttempts` | `3` | Total attempts. |
| `baseDelay` | `50` | First backoff in ms; grows exponentially with jitter. |
| `maxDelay` | `5000` | Backoff cap in ms. |
| `onRetry(error, attempt)` | none | Called before each retry. |

## Read-only refusals

`ReadOnlyError` (`TURBINE_E018`) carries a `reason`:

- **`'snapshot'`**: the database is read-only (a PowDB snapshot, or the client's `readonly: true`). Send the write to your primary.
- **`'rbac'`**: this connection's role cannot write. Connect with a writer role.
- **`'transaction'`**: the transaction is read-only (`$transaction(fn, { readOnly: true })`, `BEGIN READ ONLY`, or a hot-standby replica). PostgreSQL `25006` and MySQL 1792 map here.

```ts
import { ReadOnlyError } from 'turbine-orm';

try {
  await replica.orders.create({ data });
} catch (err) {
  if (err instanceof ReadOnlyError && err.reason === 'snapshot') {
    await primary.orders.create({ data }); // route to the writer
  }
}
```

See [Read Replicas](/read-replicas).

## Safe error messages

By default, messages leave out values a log should not hold. A `NotFoundError` names only the `where` keys:

```
[TURBINE_E001] findUniqueOrThrow on "users" found no record matching where: { id, email }
```

- `err.where` still holds the full object. It is not enumerable in safe mode, so `JSON.stringify(err)` leaves it out.
- The PostgreSQL fields that can carry a row value (`detail`, `hint`, `where`, `internalQuery`) are redacted on the error and its `.cause`.
- A value error (class `22`) names the column and describes the problem without the value.

For full messages in development, set `errorMessages: 'verbose'` on the client or call `setErrorMessageMode('verbose')`:

```ts
const db = turbine({
  connectionString: process.env.DATABASE_URL,
  errorMessages: process.env.NODE_ENV === 'development' ? 'verbose' : 'safe',
});
```

## SQLSTATE mapping

Turbine maps these PostgreSQL errors to typed classes. `wrapPgError(err)` does the same for an error you caught yourself.

| SQLSTATE | Class |
|---|---|
| `23505` | `UniqueConstraintError` (E008) |
| `23503` | `ForeignKeyError` (E009) |
| `23502` | `NotNullViolationError` (E010) |
| `23514` | `CheckConstraintError` (E011) |
| `23P01` | `ExclusionConstraintError` (E016) |
| `40P01` | `DeadlockError` (E012) |
| `40001` | `SerializationFailureError` (E013) |
| `55P03` | `LockNotAvailableError` (E013) |
| `57014` | `TimeoutError` (E002, `outcome: 'not-executed'`) |
| `25006` | `ReadOnlyError` (E018, `reason: 'transaction'`) |
| `25P02` | `TransactionRolledBackError` (E019) |
| class `08`, `28000`, `28P01`, `3D000`, `42P05`, `26000`, `53300`, `57P01`, `57P02`, `57P03`, `25P03` | `ConnectionError` (E004) |
| class `22`, `42883`, `08P01` at severity `ERROR`, `42601` from a `search` query | `ValidationError` (E003) |

## Unmapped SQLSTATEs

Any other database error keeps the driver's own class, with the SQLSTATE on `.code`:

```ts
import { TurbineError } from 'turbine-orm';

try {
  await db.orders.findMany();
} catch (err) {
  if (err instanceof TurbineError) handleTyped(err);
  else if ((err as { code?: string }).code === '42P01') runMigrations();
}
```

In verbose mode it is the raw driver error. In safe mode it is a redacted copy with the original on `.cause` and the SQLSTATE also on `.sqlstate`. Safe mode keeps the message when it cannot hold a row value and withholds it otherwise:

| Class | Message in safe mode |
|---|---|
| `42` (except `42601`), `08`, `3D`, `3F`, `53`, `57`, `58` | kept, e.g. `relation "orders" does not exist` |
| `42601`, `P0001`, `55`, everything else | withheld, naming the setting that shows it |
