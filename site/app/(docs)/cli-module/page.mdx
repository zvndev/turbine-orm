# The `turbine-orm/cli` module

`turbine-orm/cli` holds the config behind the [`turbine` CLI](/cli): the `TurbineCliConfig` type and the functions that find, load and resolve it. Most projects import only the type:

```ts
// turbine.config.ts
import type { TurbineCliConfig } from 'turbine-orm/cli';

const config: TurbineCliConfig = {
  url: process.env.DATABASE_URL,
  out: './generated/turbine',
  schema: 'public',
  migrationsDir: './turbine/migrations',
  seedFile: './turbine/seed.ts',
  schemaFile: './turbine/schema.ts',
};

export default config;
```

The module exports no commands and opens no connection, so importing it has no side effects.

## `TurbineCliConfig`

| Field | Default | Meaning |
|---|---|---|
| `url` | none | Connection string. |
| `out` | `'./generated/turbine'` | Output directory for the generated client. |
| `schema` | `'public'` | The Postgres **namespace** to introspect, not a file path. |
| `include` | `[]` | Tables to include. Empty means all. |
| `exclude` | `[]` | Tables to exclude. |
| `migrationsDir` | `'./turbine/migrations'` | SQL migration directory. |
| `seedFile` | see [`resolveSeedFile`](#resolveseedfileconfig-cwd) | Seed file path. |
| `seed` | none | Alias for `seedFile`, which wins when both are set. |
| `schemaFile` | `'./turbine/schema.ts'` | The `defineSchema` file that `push` applies and whose tags `generate` reads. A named file that is missing fails both; a missing default is skipped. |
| `columnTypes` | none | `{ 'table.column': 'TypeScript type' }`. See [Typing columns](/cli#typing-columns-columntypes). |
| `relationNames` | none | `{ table: { derivedName: newName } }`. See [Renaming derived relations](/cli#renaming-derived-relations-relationnames). |
| `importExtension` | `'auto'` | Imports in the generated `index.ts`: `'js'`, `'ts'`, `'none'`, or `'auto'` (from your tsconfig, else `'js'`). |
| `keepColumnNames` | `false` | Use raw column names as field names instead of camelCase. |
| `legacyToManyUniques` | `false` | Type a child with a unique foreign key as `hasMany` instead of `hasOne`. |
| `adapter` | none | A `DatabaseAdapter` such as `cockroachdb`. **The CLI does not read it.** |

<Callout type="warning" title="adapter is ignored by the CLI">
  `turbine migrate` does not pass `adapter` to the migration runner, so it
  takes the PostgreSQL path, including `pg_try_advisory_lock()`, which
  CockroachDB does not implement. On CockroachDB or YugabyteDB, run one
  migration job at a time yourself, or apply the generated `.sql` files with a
  tool that supports the engine. See [Compatibility](/compatibility).
</Callout>

- The module's `TurbineConfig` export is an alias of `TurbineCliConfig`, not the runtime `TurbineConfig` from the package root.
- A `schema` that looks like a file path (a `/` or `\`, or a `.ts`, `.mts`, `.cts`, `.js`, `.mjs`, `.cjs` or `.json` ending) would match no tables, so `turbine generate` refuses it. The check is the exported `looksLikeSchemaFilePath(value)`.

## Finding and loading the config

```ts
import { findConfigFile, loadConfig, loadConfigResult } from 'turbine-orm/cli';

const { config, loadError } = await loadConfigResult();
if (loadError) {
  console.error(`Failed to load ${loadError.filename}:`, loadError.error);
}
```

Candidates are `turbine.config.ts`, `turbine.config.mts`, `turbine.config.js` and `turbine.config.mjs`, in that order. The first that imports successfully wins.

| Function | Returns |
|---|---|
| `findConfigFile(cwd?)` | The first candidate that exists, or `null`. Imports nothing. |
| `loadConfig(cwd?)` | The config, or `{}`. Load errors are swallowed. |
| `loadConfigResult(cwd?)` | `{ config, loadError? }`. A file that throws is skipped for the next candidate, and the first failure is reported as `loadError: { filename, error }`. |

`unwrapModuleDefault(mod)` and `unwrapConfigModule(mod)` unwrap a module's `default` export. In a `"type": "commonjs"` project, importing `turbine.config.ts` through tsx can wrap the default twice (`{ default: { default: config } }`), which would otherwise read every field as `undefined`.

## `resolveConfig(fileConfig, overrides)`

Merges a loaded config with flag overrides and the environment into a fully defaulted `ResolvedConfig`.

```ts
import { loadConfig, resolveConfig } from 'turbine-orm/cli';

const resolved = resolveConfig(await loadConfig(), { url: argv.url, out: argv.out });
```

- A flag beats the config file, which beats the default.
- `url` alone reads the environment: `--url`, then `DATABASE_URL`, then the file's `url`. A shell `DATABASE_URL` therefore overrides the config file.
- An empty or whitespace-only value counts as unset.
- `CliOverrides` covers `url`, `out`, `schema`, `schemaFile`, `include`, `exclude`, `importExtension`, `keepColumnNames` and `legacyToManyUniques`. Everything else comes from the file.

## `resolveSeedFile(config, cwd?)`

Returns the seed file's absolute path, or `null`.

```ts
import { resolveSeedFile } from 'turbine-orm/cli';

const seed = resolveSeedFile({ seedFile: './turbine/seed.ts' });
```

An explicit `seedFile` (or `seed`) wins even when the file does not exist yet, so a typo surfaces as a missing file. Otherwise the first that exists of `seed.ts`, `seed.js`, `seed.sql`, `turbine/seed.ts`, `turbine/seed.js`, `turbine/seed.sql`.

## `configTemplate(connectionString?, schema?)`

Returns the `turbine.config.ts` source that `turbine init` writes, with `schema` defaulting to `'public'`. A connection string without a password is inlined. One with a password, or none, gives `url: process.env.DATABASE_URL`. `DEFAULT_INIT_SEED_FILE` is the seed path the template uses.
