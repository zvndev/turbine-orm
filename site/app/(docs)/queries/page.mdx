## Reading

### findMany

Returns every row matching the query.

```ts
const users = await db.users.findMany({
  where: { role: 'admin', orgId: 1 },
  orderBy: { createdAt: 'desc' },
  limit: 20,
  offset: 0,
});
```

| Option | What it does |
|---|---|
| [`where`](#filtering) | Filter rows |
| [`select` / `omit`](#selecting-fields) | Choose columns |
| [`with`](#relations-in-reads) | Load relations |
| [`orderBy`](#ordering-and-pagination) | Sort |
| [`limit` / `take`, `offset` / `skip`, `cursor`](#pagination-limit--take-offset--skip-cursor) | Page |
| [`distinct`](#distinct) | One row per distinct value (PostgreSQL) |
| [`lock`](#row-locks) | Lock the rows inside a transaction |
| [`timeout`](#per-query-timeout) | Milliseconds |
| [`includePii`](#pii-fields-includepii) | `UNSAFE` returns PII-tagged columns |
| `skipGlobalFilters` | `UNSAFE`, or `[UNSAFE, ...accessors]`, skips [global filters](/global-filters) |
| [`relationLoadStrategy`](/relations#load-strategy-auto-join-batched-flatten) | `'auto'`, `'join'`, `'batched'` or `'flatten'` |
| `jsonEncoding` | `'object'` or `'positional'` encoding for `with` rows |
| `stableRelationOrder` | Order unordered to-many relations by primary key |
| [`forceCustomPlan`](/relations#a-per-query-lever-forcecustomplan) | Plan with the real values on every run (PostgreSQL) |
| `warnOnUnlimited` | `false` silences the unlimited-query warning |

A `findMany` with no `limit`, `take` or `cursor` logs `unlimited-find-many` once per table, in production too. A `where` that pins a unique key, or a client `defaultLimit`, skips the warning.

```ts
// A tiny lookup table: no warning wanted
const roles = await db.roles.findMany({ warnOnUnlimited: false });
```

On the client, set `warnOnUnlimited: false`, or a per-table map such as `{ userProfiles: false }`. Per call beats per table, which beats global.

### findUnique / findUniqueOrThrow

Returns the row a unique key identifies, or `null`. `findUniqueOrThrow` throws `NotFoundError` ([E001](/errors#e001)) instead.

```ts
const user = await db.users.findUnique({ where: { id: 42 }, with: { posts: true } });

// Composite key: name every column
const row = await db.memberships.findUnique({ where: { userId: 1, orgId: 2 } });

// E003: an insensitive match can hit "Ada@x.com" and "ada@x.com". Use findFirst.
await db.users.findUnique({ where: { email: { equals: input, mode: 'insensitive' } } });
```

`where` must name the primary key, a unique column, every column of a compound unique, or a compound-unique selector. Each key takes a plain value or `{ equals: value }`, and extra predicates are fine.

A key compared with `null`, `in`, a range, `mode` or a column reference does not identify a row. A `where` with no identifying key throws `ValidationError` ([E003](/errors#e003)) naming the keys that work. `update`, `delete` and `upsert` follow the same rule.

### findFirst / findFirstOrThrow

Returns the first row in `orderBy` order, or `null`. `findFirstOrThrow` throws `NotFoundError` instead.

```ts
const post = await db.posts.findFirst({
  where: { authorId: 42, published: true },
  orderBy: { createdAt: 'desc' },
});
```

A `where` whose every key is `undefined` throws E003, so a missing `token` cannot match an arbitrary row. Omit `where`, or pass `{}`, to ask for any row.

## Filtering

### WHERE operators

| Operator | Matches |
|---|---|
| a value, `equals` | Equal |
| `null` | `IS NULL` |
| `not` | Not equal. `not: null` is `IS NOT NULL`; `not: { ... }` negates an operator object |
| `in`, `notIn` | Any, or none, of an array |
| `gt`, `gte`, `lt`, `lte` | Comparison |
| `contains`, `startsWith`, `endsWith` | `LIKE` substring, prefix, suffix. Wildcards in the value are escaped |
| `mode: 'insensitive'` | Case-insensitive, inside an operator on a string column |

```ts
where: {
  email: { endsWith: '@acme.com', mode: 'insensitive' },
  role: { notIn: ['banned', 'spam'] },
  score: { gte: 100 },
  title: { not: { contains: 'draft' } }, // NOT ("title" LIKE $1 ESCAPE '\')
  deletedAt: null,                        // IS NULL
}
```

- A `NULL` column matches neither a filter nor its negation. Add `{ score: null }` under an `OR` to include it.
- `mode` takes string columns, inside the operator object. On `equals`, `not`, `in` and `notIn` it compares `LOWER(...)`, which a plain btree index cannot serve: index `LOWER(col)` or use `citext`.
- `mode` on `in` / `notIn` works on PostgreSQL and PowDB. Other engines throw `UnsupportedFeatureError` ([E017](/errors#e017)); use `OR` branches.
- On MySQL, a number or boolean compared with a text column binds as text: `{ resetToken: 0 }` matches only `'0'`.
- An operand that does not fit its column throws E003: an array as a value (use `in`), a `null` range bound, or an empty operator object.

### Misspelled keys are a compile error

On a generated client, an unknown key in `where`, `orderBy`, a `with` block or a `build*` call does not compile:

```ts
await db.users.findMany({
  where: { OR: [{ emial: 'a@b.com' }] },          // type error
  with: { posts: { where: { titel: 'x' } } },     // type error
});
```

`defineSchema`-only clients and `db.table(name)` accept any `where` and `orderBy` key. `tsx` does not typecheck, so run `tsc --noEmit` in CI.

### Combinators

```ts
where: {
  AND: [{ orgId: 1 }, { role: 'admin' }],
  OR: [{ role: 'owner' }, { role: 'admin' }],
  NOT: { deletedAt: { not: null } },
}
```

`OR` takes an array. `AND` and `NOT` take an object or an array, and `NOT: [a, b]` means `NOT a AND NOT b`. `OR: []` matches no row, as in Prisma; `AND: []` and `NOT: {}` add nothing.

```ts
// Decide what zero selections mean: here, any role
const picked = selectedRoles.map((role) => ({ role }));
const rows = await db.users.findMany({ where: picked.length > 0 ? { OR: picked } : {} });
```

### `undefined` means absent

A key set to `undefined` is removed at every depth of `where`, `having`, `cursor` and `orderBy`, and so is an object it empties:

```ts
// search may be undefined: then there is no title filter
await db.posts.findMany({ where: { orgId, title: { contains: search, mode: 'insensitive' } } });
```

An emptied `where` returns every row from `findMany` and `count`, throws E003 from `findFirst`, and is refused on writes by the [mass-mutation guard](#delete--deletemany). In `data`, a top-level `undefined` field is skipped.

### Relation filters

| Operator | Matches |
|---|---|
| `some` | At least one related row matches |
| `every` | Every related row matches |
| `none` | No related row matches |
| `is` / `isNot` | The to-one target matches, or does not. `is: null` means no target |

```ts
// Users who own at least one product rated 4+
await db.users.findMany({ where: { products: { some: { data: { path: ['rating'], gte: 4 } } } } });

// Users with no posts
await db.users.findMany({ where: { posts: { none: {} } } });
```

Every operator works inside them. `some`, `every` and `none` take a where object; `is` / `isNot` take one or `null`, and only on a to-one relation. Other shapes throw E003.

### Array columns

| Operator | Matches |
|---|---|
| `has` | The array contains the element |
| `hasEvery` | The array contains every element |
| `hasSome` | The array contains at least one |

```ts
where: { tags: { hasSome: ['sql', 'mysql'] } }
```

### Full-text search

```ts
where: { body: { search: 'postgres & orm' } }
// to_tsvector('english', "body") @@ to_tsquery('english', $1)

where: { body: { search: 'orm', config: 'simple' } } // a configuration other than 'english'
```

The query is bound and uses `to_tsquery` syntax (`&`, `|`, `!`, `<->`). `config` takes letters, digits and underscores. PostgreSQL only; other engines throw E017.

### JSON columns

| Operator | Matches |
|---|---|
| `equals` with `path` | The value at `path`, compared as JSON |
| `equals` without `path` | The whole document, exactly |
| `contains` | Containment (`@>`) |
| `hasKey` | A top-level key exists |
| `gt`, `gte`, `lt`, `lte` with `path` | A range on the value at `path` |
| `stringContains`, `stringStartsWith`, `stringEndsWith` with `path` | Text at `path`, with optional `mode` |

```ts
where: { data: { path: ['meta', 'tier'], equals: 'pro' } }
where: { data: { contains: { active: true } } }    // holds these keys, maybe among others
where: { data: { path: ['rating'], gte: 4 } }      // (data #>> path)::numeric >= $1
where: { data: { path: ['title'], stringContains: 'orm', mode: 'insensitive' } }

// equals compares JSON values. Stored: { n: 5 }, { n: "5" }, { n: null }, {}
where: { data: { path: ['n'], equals: 5 } }     // only { n: 5 }
where: { data: { path: ['n'], equals: null } }  // only { n: null }: a missing key is not JSON null
```

- A numeric range operand casts to numeric; a string compares as text. Without `path`, `{ gt: 5 }` compares the column itself.
- Pathless `equals` is exact: `{ equals: { plan: 'pro' } }` does not match `{ plan: 'pro', seats: 5 }`.
- `not: <document>` means "not this document". A `not` holding only operator keys throws E003; write `NOT: { data: { ... } }`.
- An unknown key, such as Prisma's `string_contains`, or a `path` with no test throws E003.

| Engine | `equals` with `path` | `equals` without `path` |
|---|---|---|
| PostgreSQL, MySQL | Every JSON value | Exact document |
| SQL Server | Numbers and strings; arrays and objects E017 | E017 |
| SQLite | Numbers and strings; `null`, booleans, arrays and objects E017 | E017 |

SQL Server, SQLite and PowDB also refuse a bare document as a value and `not: <document>` (E017).

### Column-to-column comparison

```ts
import { col } from 'turbine-orm';

const stale = await db.modelInstances.findMany({
  where: { currentVersionId: { not: col('publishedVersionId') } },
});
// WHERE "current_version_id" != "published_version_id"
```

`col()` works with `equals`, `not`, `gt`, `gte`, `lt` and `lte`.

A plain `{ col: 'field' }` object, which `JSON.parse` can produce, throws E003, so request data cannot name a column. A reference cannot take `mode` and never identifies a row for `findUnique`, `update` or `delete`.

## Selecting fields

### select / omit

```ts
const users = await db.users.findMany({ select: { id: true, email: true } });
const safe = await db.users.findMany({ omit: { passwordHash: true } });
```

At any level, these throw E003: `select` and `omit` both naming fields; a `select` naming no field; a name that is not a column. A relation name gets [its own message](/errors#unknown-field-names) pointing at `with`.

Keys may use the field name (`lastRun`) or the column name (`last_run`), and relations their declared name (`blogPosts`) or table spelling (`blog_posts`). Both compile to the same SQL, and results use the field and declared names.

### PII fields: `includePii`

Columns tagged `pii: true` in [`defineSchema`](/schema#pii-fields) are left out of every default projection, write results included. A read returns them, at every `with` level, with `includePii: UNSAFE`.

```ts
import { UNSAFE } from 'turbine-orm';

const u = await db.users.findFirst({ where: { id: 1 } });
u.email; // undefined: email is tagged pii

// E003: select alone is not an opt-in
await db.users.findFirst({ where: { id: 1 }, select: { email: true } });

await db.users.findFirst({ where: { id: 1 }, select: { email: true }, includePii: UNSAFE });
```

<Callout type="note" title="Only the UNSAFE symbol unlocks PII">
`includePii: true` throws E003. It is a [privilege option](/global-filters#privilege-options-and-the-unsafe-symbol), and `JSON.parse` cannot produce a symbol, so `findMany({ ...req.body })` cannot read PII.
</Callout>

- Reads, streams, `groupBy` and `aggregate` take it; writes do not.
- `where`, `orderBy` and `having` on a PII column need no opt-in: they return no value.
- A PII column in the primary key is always returned.
- Grouping by a PII column, or `_min`, `_max` or `_percentile` over one, needs the opt-in. `_count`, `_sum` and `_avg` do not.
- A write `select` naming a PII column throws E003. Read the row back with `includePii: UNSAFE`.

## Ordering and pagination

### orderBy

```ts
orderBy: { lastLoginAt: { sort: 'desc', nulls: 'last' } }
// ORDER BY "last_login_at" DESC NULLS LAST

orderBy: [{ createdAt: 'desc' }, { id: 'asc' }]
// ORDER BY "created_at" DESC, "id" ASC
```

Each field takes `'asc'`, `'desc'` or `{ sort, nulls }`; an array sets precedence. Both work in `findMany`, `with` and `groupBy`. `nulls` throws E017 on MySQL and SQL Server. For vector distance, see [Vector search](/vector).

### Ordering by a relation

```ts
await db.users.findMany({ orderBy: { posts: { _count: 'desc' } } });                // to-many: _count only
await db.posts.findMany({ orderBy: { author: { name: 'asc' } } });                  // to-one: a column
await db.versions.findMany({ orderBy: { model: { category: { name: 'asc' } } } }); // a to-one chain
```

Each hop applies its target's [global filter](/global-filters). A chain allows ten hops past the first relation; one more throws `CircularRelationError` (E007). A to-many hop mid-chain throws E003: use `_count` or a pick ordering. An unknown relation throws `RelationError` (E005).

### Ordering by a JSON path

```ts
orderBy: { data: { path: ['weight'], direction: 'asc', type: 'numeric' } }
// ORDER BY ("data" #>> $1::text[])::numeric ASC NULLS LAST
```

Without `type: 'numeric'` the value compares as text. Rows missing the path sort last unless you pass `nulls`.

### Ordering by a value from one related row

```ts
orderBy: {
  versions: {
    pick: { orderBy: { createdAt: 'desc' } }, // the newest version
    by: { field: 'data', path: ['title'] },   // or by: 'title'
    direction: 'asc',
  },
}
```

`pick.orderBy` is required; `pick.where` filters first. It works on `hasMany` relations in a top-level `orderBy`, not with `distinct`. A JSON `by` is PostgreSQL only. On PostgreSQL, `plan: 'lateral'` compiles it as a `LEFT JOIN LATERAL`, which returns the same rows and can be faster on large parent sets.

### Pagination: `limit` / `take`, `offset` / `skip`, `cursor`

`take` and `skip` are aliases of `limit` and `offset`. Two different values for one bound throw E003.

```ts
const page2 = await db.posts.findMany({ orderBy: { id: 'asc' }, limit: 20, offset: 20 });

// Keyset: seek past the last row, never scanning skipped rows
const next = await db.posts.findMany({
  orderBy: { createdAt: 'desc' },
  cursor: last ? { id: last.id } : undefined, // first page: no cursor
  take: 20,
});
```

- **Order.** A cursor page follows your `orderBy` plus the primary key as tiebreaker, unless the order already holds a unique key. With no `orderBy`, it follows the primary key. A table with no primary key and no NOT NULL unique key cannot take a cursor.
- **Placing the page.** Pass every ordered field plus the key (`{ createdAt: last.createdAt, id: last.id }`; the whole last row works), or one unique key (`{ id: last.id }`). If that row is deleted, the page is empty. The cursor row is excluded.
- **Values** are plain or `{ equals: value }`. Operators, arrays, `null` on a NOT NULL column, `cursor: null`, `{}` and an all-`undefined` cursor throw E003.
- Relation, JSON-path and vector orders cannot take a cursor. Use `offset`.
- Ties are not skipped: a multi-column order seeks with `(a > $1 OR (a = $1 AND id > $2))`.

A paginated read whose `orderBy` can tie gets the same tiebreaker, so the first page matches the cursor pages:

```ts
await db.users.findMany({ orderBy: { name: 'desc' }, take: 20 });
// ORDER BY "name" DESC, "id" DESC LIMIT $1
```

### Deterministic pages: the unordered-pagination warning

A page with no `orderBy` can repeat or skip rows as the table changes, so it logs `unordered-page` once per table and shape:

```ts
await db.users.findMany({ limit: 20, offset: 40 });                        // warns
await db.users.findMany({ orderBy: { id: 'asc' }, limit: 20, offset: 40 }); // stable
```

The warning is [advice](/observability#diagnostics-diagnostics), silent under `NODE_ENV=production` by default, and follows `warnOnUnlimited`. The client option `implicitPkOrdering: true` orders such pages by primary key instead. It is off by default because it changes SQL you already send; the [`prisma-compat`](/migrate-from-prisma) adapter always applies it.

### distinct

```ts
// One post per author; orderBy picks which one survives
const sample = await db.posts.findMany({ distinct: ['userId'], orderBy: { userId: 'asc' } });
```

Sort by the `distinct` fields first. It compiles to `DISTINCT ON`, so SQLite, MySQL and SQL Server throw E017.

## Relations in reads

`with` loads relations into each row. Each takes its own `where`, `orderBy`, `limit`, `offset`, `select`, `omit` and `with`:

```ts
const users = await db.users.findMany({
  with: {
    posts: {
      where: { published: true },
      orderBy: { createdAt: 'desc' },
      limit: 5, // per user
      with: { comments: true },
    },
  },
});
users[0].posts[0].comments[0]; // fully typed
```

Nesting stops at 10 levels (E007). [Relations](/relations) covers the options and [load strategies](/relations#load-strategy-auto-join-batched-flatten).

### Counting related rows, `_count`

```ts
const users = await db.users.findMany({ with: { _count: true } });
users[0]._count; // { posts: 12, orgs: 3 }

const authors = await db.users.findMany({ with: { posts: true, _count: { posts: true } } });
authors[0]._count.posts; // 12
```

It counts `hasMany` and `manyToMany` relations; a to-one relation throws E003. Under `'auto'`, a count over an unindexed foreign key runs as one grouped follow-up query, with the same numbers.

## Writing

### create

Inserts one row and returns it, generated columns included.

```ts
const user = await db.users.create({ data: { email: 'alice@example.com', name: 'Alice', orgId: 1 } });

const event = await db.events.create({ data: {} }); // INSERT ... DEFAULT VALUES
```

Takes `data`, `select` / `omit` and `timeout`.

### Returning fewer columns

`create`, `createMany`, `update`, `delete` and `upsert` take `select` / `omit` with the read rules, checked before anything is written. Only the chosen columns cross the wire.

```ts
const { id } = await db.events.create({ data: { kind: 'click', payload }, select: { id: true } });
```

### Writing JSON columns

| Value written | Stored |
|---|---|
| An object or array | That JSON |
| A string | Raw JSON text: `'{"a":1}'` stores `{ a: 1 }` |
| `null` | SQL `NULL` |
| `jsonValue(v)` | `JSON.stringify(v)`: a JSON string, or JSON `null` |

```ts
import { jsonValue } from 'turbine-orm';

await db.docs.create({ data: { data: jsonValue('hello') } }); // the JSON string "hello"
```

On PostgreSQL, an object or array written to a built-in scalar column, such as text, a number or a date, throws E003. Pass `JSON.stringify(value)` to store it as text.

### createMany

Inserts many rows in one statement and returns them. A plain MySQL `createMany` returns `[]` ([Engines](/engines)).

```ts
const users = await db.users.createMany({
  data: [
    { email: 'a@b.com', name: 'A', orgId: 1 },
    { email: 'b@b.com', name: 'B', orgId: 1 },
  ],
});
```

| Option | What it does |
|---|---|
| `data` | The rows. Every row must name the same fields (E003 otherwise) |
| `skipDuplicates` | Skip rows that hit any unique key. E017 on SQL Server and PowDB |
| [`onConflict`](#multi-row-upsert-onconflict) | Upsert on one unique key. Not with `skipDuplicates` |
| `returning` | `false` resolves to `{ count }` |
| `select` / `omit` | Narrow the returned rows |
| `skipGlobalFilters`, `timeout` | As on `findMany` |

- A large batch is split into chunks sized to the engine's parameter and row limits, inside one transaction, so all rows land or none. Inside `$transaction`, one failed chunk rolls back every chunk, even if you catch the error.
- An oversized batch throws E017 on a pool without `connect()`, such as an HTTP driver. `buildCreateMany` is one statement, so it throws E003.
- Several all-defaults rows throw E017 on SQLite and SQL Server; call `create({ data: {} })` per row.

### Counting instead of returning rows: `returning: false`

```ts
const { count } = await db.events.createMany({ data: batch, returning: false });
```

A plain insert then sends no `RETURNING`. `count` is rows inserted or updated, never skipped ones. `select` or `omit` beside it throws E003; MySQL refuses it with `skipDuplicates` (E017).

To fill several tables together, pipeline one `buildCreateMany` per table. They share a transaction, but none sees ids another generates:

```ts
const [orders, lines] = await db.pipeline(
  db.orders.buildCreateMany({ data: orderRows, returning: false }),
  db.orderLines.buildCreateMany({ data: lineRows, returning: false }),
);
```

### Multi-row upsert: `onConflict`

```ts
import { col, expr } from 'turbine-orm';

await db.users.createMany({
  data: [{ email: 'a@b.com', name: 'A' }, { email: 'b@b.com', name: 'B' }],
  onConflict: { target: ['email'], update: ['name'] },
});
// INSERT ... ON CONFLICT ("email") DO UPDATE SET "name" = EXCLUDED."name" RETURNING *

await db.pageViews.createMany({
  data: batch,
  onConflict: {
    target: ['path'],
    update: { views: expr.add(col('views'), expr.excluded('views')) },
    where: { archived: false },
  },
});
```

| Key | What it does |
|---|---|
| `target` | The primary key or one full unique key, in any order. Not a partial index |
| `update` | Fields that take the incoming value, or a per-column object of values, [operators](#atomic-update-operators) and [expressions](#update-expressions-expr) |
| `where` | Update only matching rows; others are skipped and not returned |
| `ignore: true` | Instead of `update`: leave existing rows alone |

Two rows with one key, even keys equal only under the column's collation, throw E003 and write nothing. Global filters apply to the update, `updatedAt` is stamped unless `update` names it, and rows return in no set order.

| Engine | Statement |
|---|---|
| PostgreSQL, SQLite | `INSERT ... ON CONFLICT` |
| SQL Server | `MERGE ... WITH (HOLDLOCK)` |
| MySQL 8.0.19+ | `ON DUPLICATE KEY UPDATE`. E017 for `where`, `ignore`, a global filter, a NULL key, or a second unique key in `data` |
| PowDB | E017 |

### update / updateMany

`update` changes one row by unique key and returns it. `updateMany` changes every match and returns `{ count }`.

```ts
await db.users.update({ where: { id: 42 }, data: { name: 'Alice Updated' } });
await db.users.updateMany({ where: { role: 'guest' }, data: { role: 'member' } });
```

| Option | What it does |
|---|---|
| `where` | `update`: one row, as in [`findUnique`](#findunique--finduniqueorthrow). `updateMany`: any filter |
| `data` | Values, [operators](#atomic-update-operators) or [expressions](#update-expressions-expr) |
| `select` / `omit` | `update` only |
| `optimisticLock` | `update` only. See [Optimistic locking](/optimistic-locking) |
| `allowFullTableScan` | `UNSAFE` disarms the [mass-mutation guard](#delete--deletemany) and the one-row rule |
| `skipGlobalFilters`, `timeout` | As on `findMany` |

[`updatedAt`](/schema#auto-updated-timestamps-updatedat) columns are stamped unless named. `limit`, `take`, `offset` and `skip` on `updateMany` or `deleteMany` throw E003; select the ids first:

```ts
const batch = await db.jobs.findMany({ where: { status: 'queued' }, select: { id: true }, orderBy: { id: 'asc' }, limit: 100 });
await db.jobs.updateMany({ where: { id: { in: batch.map((j) => j.id) } }, data: { status: 'running' } });
```

### Atomic update operators

```ts
data: {
  viewCount: { increment: 1 }, // "view_count" = "view_count" + $1
  likesCount: { decrement: 1 },
  score: { multiply: 2 },
  rank: { divide: 2 },          // truncates on an integer column
  title: { set: 'New title' },
}
```

Concurrent updates cannot lose writes. On a JSON column only `set` is an operator; in `create` data an operator object is a plain value.

### Update expressions: `expr`

Build a value from the row with `expr` and `col()`. It runs inside the `UPDATE`:

```ts
import { col, expr } from 'turbine-orm';

await db.posts.update({
  where: { id: 1 },
  data: {
    viewCount: expr.add(col('viewCount'), 1),
    peakViews: expr.greatest(col('peakViews'), col('viewCount')),
    tier: expr.case([{ when: { viewCount: { gt: 1000 } }, then: 'hot' }], 'cold'),
    seenAt: expr.now(),
  },
});
```

| Builder | Notes |
|---|---|
| `expr.add`, `sub`, `mul`, `div` | Numeric. Two integers give integer math, and `div` truncates toward zero |
| `expr.coalesce`, `greatest`, `least` | 2 to 8 operands. `greatest` and `least` ignore NULLs |
| `expr.case(arms, otherwise?)` | 1 to 16 `{ when, then }` arms; `when` is a filter on the row |
| `expr.now()` | Temporal columns; UTC for zone-less ones |
| `expr.excluded('field')` | The incoming value, in `upsert` and `onConflict` updates |
| `expr.secondsBetween(a, b)` | Only in a [percentile's `of`](#percentiles-_percentile) |

- Operands are values, `col()` references or expressions, so they nest. A non-integer result into an integer column throws E003.
- Expressions throw E003 in `create` and `createMany` data, inside `{ set }`, and on JSON or array columns. PowDB and prisma-compat throw E017.
- Only `expr` builds one: a look-alike object is a value, so request data cannot become SQL.
- If your generated update types reject `expr`, regenerate the client. Lint rules banning a `then` property flag `case` arms.

### upsert

Updates the row `where` names, or inserts `create`, and returns the row. `where` must identify one row, as in `findUnique`.

```ts
const user = await db.users.upsert({
  where: { email: 'alice@example.com' },
  create: { email: 'alice@example.com', name: 'Alice', orgId: 1 },
  update: { name: 'Alice Updated' },
});
```

When every `where` key has the same value in `create`, it is one atomic `INSERT ... ON CONFLICT`. Otherwise Turbine looks the row up, then updates or inserts, in one transaction. These take the lookup:

- A `where` value that `create` lacks or contradicts.
- `update: {}`, or [nested writes](/nested-writes).
- A [global filter](/global-filters) on MySQL or SQL Server.
- On MySQL, a `create` that sets another unique key.

Like Prisma's, the lookup can race a concurrent insert, which then fails with `UniqueConstraintError` (E008). A batched `buildUpsert` refuses these shapes.

### delete / deleteMany

`delete` removes one row by unique key and returns it. `deleteMany` returns `{ count }`.

```ts
await db.users.delete({ where: { id: 42 } });
await db.users.deleteMany({ where: { createdAt: { lt: thirtyDaysAgo } } });
```

<Callout type="warning" title="Writes that would match every row are refused">
Updates and deletes throw E003 for a `where` that is empty, all `undefined`, or always true: `NOT: { OR: [] }`, `{ id: { notIn: [] } }`, an `OR` branch with no condition, and, on NOT NULL columns, `contains: ''`, `not: null` or `hasEvery: []`.
</Callout>

```ts
import { UNSAFE } from 'turbine-orm';

await db.sessions.deleteMany({ where: {}, allowFullTableScan: UNSAFE }); // every row, on purpose
```

`allowFullTableScan: true` throws; write a conditional as `...(flag ? { allowFullTableScan: UNSAFE } : {})`. A list that may be empty (`notIn: ids`) needs that decision. An always-false `where` is allowed and matches nothing.

## Aggregations

### count

```ts
const admins = await db.users.count({ where: { role: 'admin' } });
```

### aggregate

```ts
const stats = await db.posts.aggregate({
  where: { orgId: 1 },
  _sum: { viewCount: true },
  _avg: { score: true },
  _max: { createdAt: true },
  _count: true,
});
```

`_sum` and `_avg` return a `number` over `int2`, `int4` and float columns, an exact string over `int8` and `numeric`, and `null` over zero rows. `_min` / `_max` return the stored value. `groupBy` follows the same rules.

### groupBy

```ts
const postsByUser = await db.posts.groupBy({
  by: ['userId'],
  where: { published: true },
  _count: true,
  _sum: { viewCount: true },
  orderBy: { _count: 'desc' },
  limit: 10,
});
// [{ userId: 1, _count: 12, _sum: { viewCount: 4800 } }, ...]
```

| Option | What it does |
|---|---|
| `by` | A non-empty array of fields or JSON keys `{ field, path }` |
| `where` | Filter rows before grouping |
| `_count` | `true`, or `{ _all: true, title: true }` for non-NULL counts per field |
| `_sum`, `_avg`, `_min`, `_max` | `{ field: true }`, or a JSON target `{ field, path, type? }` |
| [`_percentile`](#percentiles-_percentile) | Percentiles per group |
| [`having`](#having) | Filter groups |
| `orderBy` | A `by` field, JSON key or requested aggregate |
| `limit` / `offset` | Top-N groups |
| `distinctOn` | Aggregate one row per key, picked by its `orderBy` (PostgreSQL) |

The result is typed from the args; a JSON-path key is left off the type.

```ts
const latestByCategory = await db.versions.groupBy({
  distinctOn: { columns: ['instanceId'], orderBy: { createdAt: 'desc' } },
  by: [{ field: 'data', path: ['category'] }],         // result key: 'category'
  _sum: { price: { field: 'data', path: ['price'] } },  // cast to numeric
});
```

### HAVING

```ts
const busy = await db.posts.groupBy({
  by: ['typeId'],
  _count: true,
  _sum: { viewCount: true },
  having: {
    typeId: { not: null },             // the grouped value
    _count: { gt: 1 },                 // the row count
    viewCount: { _sum: { gte: 100 } }, // a column aggregate
  },
});
// HAVING "type_id" IS NOT NULL AND COUNT(*) > $1 AND SUM("view_count") >= $2
```

Aggregate filters take `equals`, `not`, `gt`, `gte`, `lt`, `lte`, `in` and `notIn`. A grouped-value filter takes any [WHERE operator](#where-operators), on a `by` field only (E003 otherwise). `AND`, `OR` and `NOT` nest as in [`where`](#combinators).

### Percentiles: `_percentile`

```ts
import { col, expr } from 'turbine-orm';

const stats = await db.requests.aggregate({
  _percentile: {
    latencyMs: { p: [0.5, 0.95, 0.99] },  // [median, p95, p99]
    sizeBytes: { p: 0.5, method: 'disc' }, // a stored value
    wait: { of: expr.secondsBetween(col('requestedAt'), col('readyAt')), p: 0.95 },
  },
});
```

`p` is a fraction, or an array of them. `method: 'cont'` (default) interpolates over numeric and interval columns; `'disc'` returns a stored value. Over zero rows the result is `null`.

A key that names no field takes `of`, a numeric [expression](#update-expressions-expr), and returns a `number`. Integer division in it truncates, so multiply by a fraction instead.

PostgreSQL only (E017 elsewhere). A PII column needs `includePii: UNSAFE`.

## Streaming

### findManyStream

Yields rows through an async iterator. On PostgreSQL it reads a server-side cursor in constant memory. SQLite, MySQL and SQL Server load the result, then yield it in batches.

```ts
for await (const user of db.users.findManyStream({ where: { orgId: 1 }, batchSize: 1000, with: { posts: true } })) {
  process.stdout.write(`${user.email}\n`);
}

// One array per fetch, without a promise per row
for await (const batch of db.users.findManyStreamBatches({ where: { orgId: 1 }, batchSize: 500 })) {
  await sink.writeAll(batch);
}
```

Both take `findMany`'s options except `lock`, plus `batchSize` (default 1000) and `idleTimeoutMs`. A result that fits one batch skips the cursor. Breaking out releases the connection.

### Abandoned streams close themselves

A stream holding a cursor closes after five minutes without a pull. It logs `stream-idle-timeout`, and the next pull throws `TimeoutError` (E002).

```ts
// Per call: a consumer that pauses for up to 30 minutes
for await (const row of db.events.findManyStream({ idleTimeoutMs: 30 * 60_000 })) {
  await slowSink.write(row);
}

// Per client. 0 disables it.
const db = turbine({ connectionString: process.env.DATABASE_URL, streamIdleTimeoutMs: 0 });
```

A stream inside `$transaction` is bounded by the transaction's timeout. On PostgreSQL the server also ends the stream's transaction if the process freezes.

## Raw SQL

```ts
const stats = await db.raw<{ day: Date; count: number }>`
  SELECT DATE_TRUNC('day', created_at) AS day, COUNT(*)::int AS count
  FROM posts WHERE org_id = ${orgId}
  GROUP BY day ORDER BY day
`;

// SQL text built at runtime: $n placeholders, values after
const table = 'audit_' + year; // from your own code, never from a request
const rows = await db.rawUnsafe(`SELECT * FROM ${table} WHERE actor_id = $1`, actorId);
```

- Every `${}` in `db.raw` and `db.sql` is a bound parameter. They take only a real tagged template.
- `rawUnsafe` escapes nothing in its text. Never let untrusted input reach it.
- Write `$1`, `$2` on every engine; Turbine rewrites them for SQLite, MySQL and SQL Server.
- Raw SQL emits `$on('query')` events but skips `$use` middleware.

### Typed raw SQL: `db.sql<T>`

```ts
const users = await db.sql<{ id: number; name: string }>`SELECT id, name FROM users WHERE org_id = ${orgId}`;
const user = await db.sql<{ id: number; name: string }>`SELECT id, name FROM users WHERE id = ${42}`.one();
const total = await db.sql<{ count: number }>`SELECT COUNT(*)::int AS count FROM users`.scalar();
```

Awaiting returns `T[]`. `.one()` returns the first row or `null`; `.scalar()` the first column of the first row, or `null`.

## Client tools

### Pipeline

Runs independent queries in one round trip. Each method's `build*` twin returns the query without running it.

```ts
const [user, postCount, recentPosts] = await db.pipeline([
  db.users.buildFindUnique({ where: { id: 1 } }),
  db.posts.buildCount({ where: { orgId: 1 } }),
  db.posts.buildFindMany({ where: { userId: 1 }, limit: 5 }),
]);
```

By default a pipeline is one transaction: any failure, including an `*OrThrow` miss, rolls it back. Pass `{ transactional: false }` to isolate failures:

```ts
import { PipelineError } from 'turbine-orm';

try {
  await db.pipeline(queries, { transactional: false });
} catch (err) {
  if (err instanceof PipelineError) {
    // err.results: per query, { status: 'ok', value } or { status: 'error', error }
  }
}
```

HTTP pools without pipelining run the queries in turn; check with `await db.pipelineSupported()`. Nested writes have no `build*` twin.

### Transactions

```ts
await db.$transaction(
  async (tx) => {
    const user = await tx.users.create({ data: { email: 'new@example.com', name: 'New', orgId: 1 } });
    await tx.posts.create({ data: { userId: user.id, orgId: 1, title: 'Hello', content: '...' } });
  },
  { isolationLevel: 'Serializable', timeout: 5000 },
);

// Or a batch of build* queries on one connection
const [order, user] = await db.$transaction([
  db.orders.buildCreate({ data: { userId: 1, total: 4200 } }),
  db.users.buildUpdate({ where: { id: 1 }, data: { orderCount: { increment: 1 } } }),
]);
```

`tx` has the same accessors as `db`, and a nested `$transaction` is a savepoint. See [Transactions](/transactions).

### Row locks

`findMany`, `findFirst`, `findUnique` and their `*OrThrow` forms take `lock`, held until the transaction ends:

```ts
await db.$transaction(async (tx) => {
  const job = await tx.jobs.findFirst({
    where: { status: 'queued' },
    orderBy: { id: 'asc' },
    lock: { mode: 'update', skipLocked: true }, // FOR UPDATE OF "jobs" SKIP LOCKED
  });
  if (job) await tx.jobs.update({ where: { id: job.id }, data: { status: 'running' } });
});
```

| `lock` | SQL |
|---|---|
| `'update'`, `'noKeyUpdate'`, `'share'`, `'keyShare'` | `FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR SHARE`, `FOR KEY SHARE` |
| `{ mode, noWait: true }` | Fail at once on a locked row |
| `{ mode, skipLocked: true }` | Leave locked rows out |

- Only the queried table is locked, not rows loaded by `with`.
- Outside a transaction, on a stream, or with `distinct`, it throws E003.
- MySQL takes `'update'` and `'share'`; SQLite, SQL Server and PowDB throw E017.

A lock that cannot be taken throws [`LockNotAvailableError`](/errors#e013), which is retryable. On PostgreSQL it aborts the transaction, so try uncertain locks in a nested block:

```ts
import { LockNotAvailableError } from 'turbine-orm';

await db.$transaction(async (tx) => {
  try {
    await tx.$transaction((inner) =>
      inner.accounts.findUnique({ where: { id }, lock: { mode: 'update', noWait: true } }),
    );
  } catch (err) {
    if (!(err instanceof LockNotAvailableError)) throw err;
    // Only the savepoint rolled back.
  }
});
```

### Per-query timeout

Every method takes `timeout` in milliseconds, or `0` for none.

```ts
import { TimeoutError } from 'turbine-orm';

try {
  await db.orders.update({ where: { id }, data: { status: 'shipped' }, timeout: 2_000 });
} catch (err) {
  if (err instanceof TimeoutError && err.outcome === 'not-executed') {
    // Nothing changed: safe to retry.
  }
}
```

A `TimeoutError` ([E002](/errors#e002)) carries `outcome`. `'not-executed'` means nothing changed, for example when the PostgreSQL server confirms Turbine's cancel. `'unknown'` means a write may have applied, which is the answer on other engines; check before retrying.

Inside `$transaction` on PostgreSQL, a timed-out statement rolls the transaction back, and `$transaction` rejects with `TransactionRolledBackError` ([E019](/errors#e019)) even if you catch the timeout.

### Middleware

```ts
db.$use(async (params, next) => {
  const start = Date.now();
  const result = await next(params);
  console.log(`${params.model}.${params.action} took ${Date.now() - start}ms`);
  return result;
});
```

Middleware can read `params`, time the call and transform the result. It cannot change the query: editing `params.args` makes `next()` throw a `TypeError`. Put tenant and soft-delete filters in a [global filter](/global-filters).

### explain

```ts
const plan = await db.posts.explain({ where: { orgId: 7 }, orderBy: { createdAt: 'desc' } });
// ['Sort  (cost=…)', '  ->  Index Scan using posts_org_id_idx on posts …', …]
```

Returns the plan for the statement `findMany(args)` would run, as lines. SQLite uses `EXPLAIN QUERY PLAN`, PowDB its own `explain`, and SQL Server throws E017. Match node names, not layout.

### Client configuration

`turbine()` and `new TurbineClient()` take a `TurbineConfig`. [Quick Start](/quickstart) and [Serverless](/serverless) cover the connection fields.

```ts
const db = turbine({ connectionString: process.env.DATABASE_URL, poolSize: 20 });
```

| Option | Default | What it does |
|---|---|---|
| `poolSize` | `10` | Maximum connections |
| `idleTimeoutMs` | `30000` | Close an idle connection |
| `connectionTimeoutMs` | `5000` | Give up acquiring a connection (E004) |
| `maxLifetimeSeconds` | `1800` | Replace an old connection when idle |
| `preparedStatements` | `true` | Named statements; `false` for external pools and poolers |
| `statementTimeoutMs` | unset | PostgreSQL `statement_timeout` per statement |
| `streamIdleTimeoutMs` | `300000` | [Close an abandoned stream](#abandoned-streams-close-themselves) |
| `sqlCache` / `sqlCacheSize` | `true` / `1000` | Per-table SQL template cache |
| `implicitPkOrdering` | `false` | [Order unordered pages](#deterministic-pages-the-unordered-pagination-warning) by primary key |
| `planCacheMode` | unset | PostgreSQL [`plan_cache_mode`](/relations#the-generic-plan-cliff-plancachemode) |
| `utcTimestamps` | `true` | [Zone-less columns as UTC](/schema#zone-less-columns-timestamp-and-date-read-as-utc) |
| `temporalInfinity` | `'preserve'` | [`infinity`](/schema#infinity-and--infinity) as `Infinity`, or `'null'` |
| `sqlComment` | unset | [sqlcommenter](/observability#sql-comments-sqlcomment) tags |
| `logger` | `console` | [Log output](/observability#log-output-logger); `{}` silences it |
| `diagnostics` | from `NODE_ENV` | [Advice and self-checks](/observability#diagnostics-diagnostics) |
| `autoToOneJoinMaxRows` | `1000` | Row ceiling for the [`'auto'` to-one rule](/relations#load-strategy-auto-join-batched-flatten) |

- `max`, `idleTimeoutMillis` and `connectionTimeoutMillis` work as aliases.
- An unknown key logs `unknown-config-key` with the nearest option, and never throws.
- Behind a transaction pooler Turbine does not recognize, set `preparedStatements: false`, or queries fail with `prepared statement "..." does not exist`.
- Each connection keeps every named statement it parses. Build `select`, `omit` and `with` from user input only through a fixed allowlist.
