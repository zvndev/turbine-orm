# Seeding

`turbine seed` runs a seed file to populate your database. The file can be TypeScript, JavaScript or SQL, and Turbine picks the right runner for each. TypeScript seeds run through `tsx`, so there is no build step.

```bash
npx turbine seed
```

## `defineSeed`, TypeScript seeds

`defineSeed` wraps a function that receives a connected client. It reads `DATABASE_URL`, runs your function and disconnects afterwards, so you never manage the connection.

When `turbine.config.ts` sets a `schema` other than `public`, `turbine seed` pins `search_path` to it in the connection's startup parameters (`options=-c search_path="<schema>"`, never a `SET`). Unqualified table names in the seed then land in the same schema `push`, `generate` and `migrate` use.

```ts
// seed.ts
import { defineSeed } from 'turbine-orm';

export default defineSeed(async (db) => {
  await db.raw`
    INSERT INTO organizations (name, slug) VALUES (${'Acme'}, ${'acme'})
    ON CONFLICT (slug) DO NOTHING
  `;
  console.log('Seeded.');
});
```

The `db` passed to the callback is a base client, so write with [`db.raw`](/queries#raw-sql) or [`db.sql`](/queries#typed-raw-sql-dbsqlt). For typed table accessors, import your generated client instead and manage its lifecycle yourself:

```ts
// seed.ts
import { turbine } from './generated/turbine/index.js';

const db = turbine({ connectionString: process.env.DATABASE_URL });

await db.organizations.createMany({
  data: [
    { name: 'Acme', slug: 'acme' },
    { name: 'Widgets', slug: 'widgets' },
  ],
});

await db.disconnect();
```

Both files run the same way: `npx turbine seed`. A TypeScript seed that does not call `defineSeed`, like the second one, runs to completion and exits `0`, with a notice that Turbine cannot confirm what it wrote.

## JavaScript and SQL seeds

- **`.js`**: imported dynamically. If the default export is a function, Turbine calls it.
- **`.sql`**: executed as raw SQL against the database.

```sql
-- seed.sql
INSERT INTO organizations (name, slug) VALUES ('Acme', 'acme')
ON CONFLICT (slug) DO NOTHING;
```

> **Note:** TypeScript seeds need `tsx`, which most TypeScript projects already have as a dev dependency. If it is missing, Turbine tells you to install it or use a `.js` / `.sql` seed.

## File resolution

Turbine resolves the seed file in this order:

1. The `seedFile` field in `turbine.config.ts`. An explicit path always wins, even if the file does not exist yet.
2. The first default candidate found: `seed.ts`, `seed.js`, `seed.sql`, `turbine/seed.ts`, `turbine/seed.js`, `turbine/seed.sql`.

```ts
// turbine.config.ts
import type { TurbineCliConfig } from 'turbine-orm/cli';

export default {
  url: process.env.DATABASE_URL,
  seedFile: './turbine/seed.ts',
} satisfies TurbineCliConfig;
```

`seedFile` is the canonical key, and the one `turbine init` writes. `seed` is a back-compat alias. When both are set, `seedFile` wins.

## Seeding in CI/CD

Run `migrate deploy`, then `seed`. `migrate deploy` applies pending migrations without prompts, so it is safe in a pipeline:

```bash
# CI: bring a fresh database up to date, then seed it
npx turbine migrate deploy
npx turbine seed
```

`migrate deploy` exits `1` on a checksum mismatch or a missing migration file, so a drifted migration history fails the build instead of diverging unnoticed. See [`migrate deploy`](/cli#turbine-migrate-deploy).
