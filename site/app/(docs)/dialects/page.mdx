# Writing a custom dialect

A dialect adds an engine Turbine does not ship. It is one object, typed `Dialect`, that builds every piece of SQL that differs between engines. The shipped SQLite, MySQL and SQL Server engines are dialects too.

```ts
import {
  postgresDialect,
  type Dialect,
  type DialectName,
  type EngineCapabilities,
  type ResultStrategy,
  type BuiltStatement,
  type InsertStatementInput,
  type BulkInsertStatementInput,
  type UpsertStatementInput,
  type ColumnTypeInput,
  type ColumnDefinitionInput,
  type CreateTableStatementInput,
  type CreateIndexStatementInput,
  type StreamableConnection,
  type DialectIntrospector,
  type DialectIntrospectOptions,
} from 'turbine-orm';
```

<Callout type="note" title="Do you need one?">
  A database that speaks the PostgreSQL wire protocol (CockroachDB, YugabyteDB,
  AlloyDB, TimescaleDB, Neon, Supabase) needs no dialect, at most a thin
  [adapter](/compatibility). An engine with no SQL at all cannot be a dialect:
  see [PowDB](/powdb), which replaces query generation instead.
</Callout>

## Start from `postgresDialect`

Spread the PostgreSQL dialect and override what differs:

```ts
import { postgresDialect, TurbineClient, type Dialect } from 'turbine-orm';

export const myDialect: Dialect = {
  ...postgresDialect,
  name: 'myengine',
  capabilities: {
    ...postgresDialect.capabilities,
    distinctOn: false,
    positionalJson: false,
    nullsSortHigh: false,
    readOnlyTransactions: false,
    backendCancel: false,
    abortsTransactionOnError: false,
    statementSyntax: null,
    // ...every other key your engine answers differently
  },
  paramPlaceholder: (i) => `@p${i}`,
  supportsVector: false,
  supportsListenNotify: false,
};

const db = new TurbineClient({ pool: myPoolShim, dialect: myDialect }, SCHEMA);
```

The pool shim implements `PgCompatPool`: `query(text, values)`, `connect()` and `end()`. That is the whole driver contract.

## Engine capabilities: what the engine is, not what it is called

`capabilities` (type `EngineCapabilities`) says what the engine can do. Turbine reads these keys rather than `dialect.name`. The object is required: `TurbineClient` refuses a dialect without one with `ValidationError` ([`TURBINE_E003`](/errors#e003)).

A spread copies PostgreSQL's answers under your new name. Go through every key: a wrong `true` becomes a failing query at runtime, while a correct `false` becomes a clear `TURBINE_E017`. The shipped `sqliteDialect`, `mysqlDialect` and `mssqlDialect` (from their subpaths) are worked examples.

## Feature flags

Feature flags sit at the top level of the dialect. Most gate a feature: when off, using it throws `UnsupportedFeatureError` ([`TURBINE_E017`](/errors#e017)) instead of emitting SQL that cannot work. A few choose a SQL shape instead. `jsonPathSupport` (required) is `'native'`, `'function'` or `'limited'`.

| Flag | Required | When `false` or absent |
|---|:-:|---|
| `supportsReturning` | yes | No `RETURNING`; set `resultStrategy` to match |
| `supportsILike` | yes | `buildInsensitiveLike` supplies the equivalent |
| `supportsVector` | yes | pgvector filters and ordering throw |
| `supportsJsonContains` | yes | Pathless JSON `contains` / `equals` throw |
| `supportsListenNotify` | yes | `$listen` / `$notify` throw |
| `supportsRLS` | yes | `sessionContext` throws |
| `supportsAdvisoryLock` | yes | Migration locking needs a `DatabaseAdapter` |
| `aggSupportsInlineOrderBy` | yes | Ordered to-many relations use a subquery |
| `supportsUpsertUpdateWhere` | no | An upsert under a global filter looks the row up first. Set `true` only if `buildUpsertStatement` emits `updateWhere`. |
| `supportsFullTextSearch` | no | `search` throws |
| `supportsArrayColumns` | no | `has` / `hasEvery` / `hasSome` / `isEmpty` throw |
| `supportsLateralJoin` | no | `plan: 'lateral'` pick-row ordering throws |
| `supportsPlanCacheMode` | no | `planCacheMode` and `forceCustomPlan` throw |
| `supportsPercentileAggregates` | no | `_percentile` throws |
| `supportsBulkUpsert` | no | `createMany({ onConflict })` throws |
| `rowLockModes` | no | Every `lock` throws. Set the allowed strengths. |
| `explainQuery` | no | `explain()` throws. Set `{ prefix }`. |
| `inlineLimitOffset` | no | `LIMIT` / `OFFSET` are bound (MySQL inlines validated integers) |

An absent optional flag means off, but a spread is not absence: it carries PostgreSQL's value. Set every flag your engine answers differently as its own property.

## `resultStrategy`

```ts
type ResultStrategy = 'returning' | 'output' | 'reselect';
```

| Strategy | How a write returns its row | Used by |
|---|---|---|
| `'returning'` | Trailing `RETURNING *` | PostgreSQL, SQLite 3.35+ |
| `'output'` | `OUTPUT INSERTED.*` / `MERGE` in the same statement | SQL Server |
| `'reselect'` | The write, then a `SELECT` by key or `where` | MySQL |

A reselect is a second statement. It cannot return rows it has no key for, which is why a plain `createMany` on MySQL returns `[]`.

## Required methods

- **Values:** `paramPlaceholder(index)`, `quoteIdentifier(name)`, `escapeStringLiteral(value)`. Return a numbered placeholder (`$1`, `:p1`, `@p1`), not `?`: parameters are pushed in build order, which is not always text order.
- **JSON nesting:** `buildJsonObject`, `buildJsonArrayAgg`, `wrapJsonSubresult`, `emptyJsonArrayLiteral`, `nullJsonLiteral`, `buildJsonContains`, `buildJsonPathExtract`. An empty to-many must come back `[]` and a missing to-one `null`.
- **Statements:** `buildReturningClause`, `buildInsertStatement`, `buildBulkInsertStatement`, `buildUpsertStatement`, `buildInsensitiveLike`, `buildCorrelation`.
- **DDL:** `buildColumnType`, `buildColumnDefinition`, `buildPrimaryKeyConstraint`, `buildCreateTableStatement`, `buildCreateIndexStatement`.
- **Migration tracking:** `buildMigrationTrackingTable`, `buildMigrationSelectApplied`, `buildMigrationUpdateChecksum`, `buildMigrationInsertApplied`, `buildMigrationDeleteApplied`.
- **Transactions:** `beginStatement`, `commitStatement`, `rollbackStatement`, `savepointStatement`, `releaseSavepointStatement`, `rollbackToSavepointStatement`, `buildSetSessionConfig`.
- **Streaming:** `openStream(connection, sql, params, batchSize)`, an async generator of row batches. Only PostgreSQL's runs a server-side cursor; the other shipped dialects load the result, then yield it in batches.

## Optional hooks

An omitted hook falls back to the PostgreSQL behavior.

| Hook | Override it when |
|---|---|
| `castAggregate` | There is no `::` cast (SQLite) |
| `buildInClause` + `inClauseParam` | There are no array parameters. Override both or neither. |
| `escapeLikePattern` + `likeEscapeCharacter` | `LIKE` needs other escaping (SQL Server's `[`, MySQL's `!`) |
| `buildLimitOffset`, `buildUpdateStatement`, `buildDeleteStatement` | The statement shape differs (SQL Server's `OFFSET ... FETCH` and mid-statement `OUTPUT`) |
| `buildRelationSubquery` | JSON aggregation cannot use the primitives (SQL Server's `FOR JSON PATH`) |
| `buildEnumColumn` | Enums are not named types |
| `checkTextWrite` | The engine stores bad text in a numeric column instead of refusing it (SQLite) |
| `jsonWireRule`, `decodeColumnValue`, `averageArgument` | Values differ inside JSON, from storage, or from `AVG` |
| `buildJsonPathEquals` | JSON `{ path, equals }` should compare typed values |
| `buildBulkUpsertStatement`, `buildJsonArray`, `buildPartitionLimit` | You turn on `supportsBulkUpsert`, `positionalJson` or `partitionLimitPushdown` |
| `buildDefaultValuesInsertStatement`, `arrayType`, `typeToTypeScript`, `introspector` | All-defaults inserts, array casts, type mapping or catalog reads differ |

<Callout type="warning" title="buildRelationSubquery owns parameter order">
  Push parameters in exactly the order their placeholders appear in the
  assembled statement. Getting this wrong returns the wrong rows with no error.
  Read `RelationSubqueryContext` before you start.
</Callout>

`DialectMigrator` is deprecated and unused. Migration locking lives in a `DatabaseAdapter`.

## Checklist

1. Set every `capabilities` key and feature flag from measured behavior.
2. Pick the `resultStrategy` that matches the engine, and document its limits if it is not `'returning'`.
3. Test nested `with` at depth, an ordered to-many with a per-relation `limit`, a composite-key relation, an empty to-many (`[]`) and a missing to-one (`null`).
4. Check that `quoteIdentifier` survives identifiers containing quote characters.
5. Confirm every value reaches the database as a bound parameter.
