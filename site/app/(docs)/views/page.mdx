# Views & Generated Columns

Turbine generates read-only accessors for database views, and treats `STORED` generated columns as readable but never writable. Both rules hold in the generated types and again at runtime.

## Views

Pass `--include-views` to introspect views and materialized views along with tables:

```bash
npx turbine generate --include-views
```

Each view gets an entity type and the read methods (`findMany`, `findFirst`, `count`, `aggregate` and the rest):

```ts
// active_users is a Postgres view
const active = await db.activeUsers.findMany({
  where: { orgId: 1 },
  orderBy: { name: 'asc' },
});
```

### Views are read-only

Every write method on a view throws `ValidationError` ([E003](/errors#e003)) before any SQL runs, on every SQL engine:

```ts
await db.activeUsers.create({ data: { name: 'x' } });
// ValidationError: Cannot create "active_users": it is a view (read-only).
```

### Views without a primary key

A view with no primary key cannot address one row, so its accessor has no `findUnique` or `findUniqueOrThrow`. Calling either is a compile error. A view that exposes a primary key keeps the full read API.

## STORED generated columns

Postgres computes a `GENERATED ALWAYS AS (...) STORED` column from other columns:

```sql
CREATE TABLE invoices (
  id    bigserial PRIMARY KEY,
  qty   integer NOT NULL,
  price integer NOT NULL,
  total integer GENERATED ALWAYS AS (qty * price) STORED
);
```

`total` is in the `Invoice` entity type and comes back on every read. It is left out of `InvoiceCreate` and `InvoiceUpdate`, so writing it is a compile error. Untyped data that reaches `create`, `update` or `upsert` with the column throws `ValidationError` ([E003](/errors#e003)):

```ts
await db.invoices.create({ data: { qty: 2, price: 3 } });           // total = 6
await db.invoices.create({ data: { qty: 2, price: 3, total: 6 } }); // ValidationError
```
