# Migrating from Prisma

Turbine's query API is close to Prisma's, so most of a migration is mechanical, and you can do it one module at a time:

1. Add the foreign-key indexes Prisma never needed, with `turbine doctor`.
2. Run `turbine migrate-from-prisma` to generate a typed client and a Prisma-to-Turbine name map.
3. Swap `new PrismaClient()` for the compat client, so existing call sites keep working.
4. Port modules to native `db.<table>` calls one at a time, then remove the compat client.

You can skip step 3 and port directly. Steps 1 and 2 still apply.

## Before anything else: run doctor

Prisma does not index foreign keys on PostgreSQL, and its batched loading rarely needs them. Turbine's default plan probes the child table once per parent row, so an unindexed foreign key costs a table scan per parent. On one dataset that was 17.8 s without the index and 62 ms with it.

```bash
npx turbine doctor --fix
npx turbine migrate up
```

`doctor` lists every relation whose foreign key (or junction key) has no covering index, and `--fix` writes a migration that adds them. See [`turbine doctor`](/doctor).

Until the indexes exist, `relationLoadStrategy: 'batched'` loads relations the way Prisma does, one query per relation:

```ts
import { turbine } from './generated/turbine/index.js';

const db = turbine({ relationLoadStrategy: 'batched' });
```

Both strategies return the same rows ([load strategies](/relations#load-strategy-auto-join-batched-flatten)).

## The migration toolkit

The toolkit has two parts: a CLI command that resolves `schema.prisma` against your database, and `turbine-orm/prisma-compat`, a runtime adapter that serves Prisma's client API from the map the command writes.

### `turbine migrate-from-prisma`

```bash
DATABASE_URL=postgres://... npx turbine migrate-from-prisma --schema prisma/schema.prisma
```

The command does not need `prisma` or `@prisma/client` installed. It writes to your generate output directory (`./generated/turbine` by default):

| File | Contents |
|---|---|
| `prisma-migration-report.md` | Per-model resolution, many-to-many relations to audit, implicit junction tables, enums, unresolved items and parser notes. Read it first. |
| `prisma-map.ts` | `PRISMA_MAP`, the typed name map the compat client reads. |
| `types.ts`, `metadata.ts`, `index.ts` | The standard generated client, as `turbine generate` writes it. |

| Flag | Effect |
|---|---|
| `--schema <path>` | The Prisma schema file, or a directory of `.prisma` files. Default `prisma/schema.prisma`, then `prisma/schema/`. In this command `--schema` never names a Postgres schema; the namespace is `public`. |
| `--url`, `-u <url>` | Connection string. Falls back to `DATABASE_URL`, `url` in `turbine.config.ts`, then the schema's `datasource` block. |
| `--out`, `-o <dir>` | Output directory. It must be inside the current directory ([why](/cli#the---out-directory-guard)). |
| `--no-db` | Parse only: writes the report, but no map and no client. |
| `--allow-partial` | Exit 0 when some items are unresolved. By default the command exits 1. |
| `--if-db` | Exit 0 without doing anything when no connection string resolves. For `postinstall`. |
| `--no-timestamp` | Omit the generated-at line, so reruns are byte-identical. |

An unresolved item never blocks the client; the compat client just does not know that one Prisma name.

### Keeping the map current

`prisma-map.ts` is a snapshot of your schema. Regenerate it next to `prisma generate` and commit it with every `schema.prisma` change:

```json
{
  "scripts": {
    "postinstall": "prisma generate && turbine migrate-from-prisma --if-db"
  }
}
```

To make CI enforce it, regenerate against a real database and fail on a diff:

```bash
turbine migrate-from-prisma --no-timestamp
git diff --exit-code generated/turbine/prisma-map.ts
```

The compat client also checks at startup. When `schema.prisma` has changed since the map was generated, it logs one warning (code `prisma-map-stale`) naming the command to rerun. The check runs in production too, and never throws.

### `createPrismaCompatClient`

```ts
// db.ts
import { createPrismaCompatClient } from 'turbine-orm/prisma-compat';
import { turbine } from './generated/turbine/index.js';
import { PRISMA_MAP } from './generated/turbine/prisma-map.js';

export const db = turbine();
export const prisma = createPrismaCompatClient(db, PRISMA_MAP);
```

Swap `prisma` in for `new PrismaClient()` and existing call sites keep working:

```ts
const users = await prisma.user.findMany({
  where: { email: { contains: '@acme.com' } },
  include: { posts: { orderBy: { createdAt: 'desc' }, take: 5 } },
});
```

Models are available under both spellings, `prisma.User` and `prisma.user`. The adapter translates:

- `include` to `with`, `select` into columns plus relations, and field and relation renames in both directions
- `take`, `skip` and `cursor`, with Prisma's cursor semantics (see [Cursor pagination](#cursor-pagination))
- compound-unique selectors, including custom `@@unique(name:)` names
- `$transaction` in callback and array form, including `isolationLevel` and `timeout`
- `$queryRaw`, `$executeRaw` and their `Unsafe` variants, on the client and inside `$transaction`
- `createMany({ skipDuplicates })`, `_count`, `distinct` and `groupBy`
- `@default(uuid())`, `@default(cuid())` and `@updatedAt`, which Prisma fills in the client
- to-one relations, returned as `object | null`

Implicit many-to-many junction tables have no Prisma model, so they are exposed under their raw table name (`prisma._PostToTag`) at runtime only. Reaching one needs a cast.

| Option | Default | What it does |
|---|---|---|
| `prismaErrorCodes` | `false` | Sets `.code` on thrown errors to the nearest Prisma code (`P2002`, `P2025`, ...). |
| `stablePkOrder` | `false` | Orders every to-many relation without an `orderBy` by the target's primary key. |

```ts
const prisma = createPrismaCompatClient(db, PRISMA_MAP, { prismaErrorCodes: true });
```

### Client extensions

`$extends` supports the `client` and `model` components, in object form and through `Prisma.defineExtension`. It returns a new client and can be chained. `model` members are available inside `$transaction`; `client` members are not, because they usually close over the base client.

`query` and `result` throw `UnsupportedFeatureError` ([E017](/errors#e017)) when you call `$extends`. For logging or timing, use `db.$use` on the underlying client; compute derived fields in application code.

### Turbine-native query options

The adapter passes Turbine-only options straight through:

```ts
const rows = await prisma.order.findMany({
  where: { tenantId },
  take: 20,
  forceCustomPlan: true,
});
```

The forwarded options are `timeout`, `forceCustomPlan`, `warnOnUnlimited`, `stableRelationOrder`, `jsonEncoding`, `lock`, `skipGlobalFilters`, `allowFullTableScan` and `includePii`, each on the operations that take it natively. `optimisticLock` and `groupBy`'s `distinctOn` are forwarded too; they name fields, so write them in Prisma field names.

<Callout type="warning" title="Privilege options need the UNSAFE symbol">
  `skipGlobalFilters`, `includePii` and `allowFullTableScan` are
  [privilege options](/global-filters#privilege-options-and-the-unsafe-symbol).
  `true` throws `ValidationError` ([E003](/errors#e003)). Pass the imported
  symbol:

  ```ts
  import { UNSAFE } from 'turbine-orm';

  await prisma.post.findMany({ where: { authorId: 1 }, skipGlobalFilters: UNSAFE });
  await prisma.post.deleteMany({ allowFullTableScan: UNSAFE });
  ```
</Callout>

An unknown option logs a one-time warning with a suggested spelling (codes `prisma-compat-unknown-option` and `prisma-compat-native-spelling`) while [diagnostics advice](/observability#diagnostics-diagnostics) is on. It never throws.

### What the adapter does not do

- **`$use` and `$on` do not exist** on the compat client. Turbine's `db.$use` middleware can observe a query but not rewrite it (editing `params.args` throws a `TypeError`), so move tenant or soft-delete conditions into [global filters](/global-filters).
- **`$connect()` and `$disconnect()` do nothing.** The `TurbineClient` owns the pool, so call `db.disconnect()` in tests and serverless teardown.
- **Fluent relation chaining** (`prisma.user.findUnique(...).posts()`), Accelerate, Pulse, the MongoDB API and the `prisma migrate` CLI are not supported.
- **Errors are not `PrismaClientKnownRequestError`.** Catch Turbine's [typed errors](/errors), or turn on `prismaErrorCodes`.

These throw instead of returning a subtly wrong result:

- `UnsupportedFeatureError` ([E017](/errors#e017)): a negative `take`, `cursor` or `distinct` on an included relation, a filtered relation `_count`, `take`/`skip`/`cursor` on `count` or `aggregate`, `limit` on `updateMany`/`deleteMany`, a relation in a write's `include` or `select`, and `createMany({ skipDuplicates })` on SQL Server and PowDB.
- `ValidationError` ([E003](/errors#e003)): an unknown key on an included relation (including Turbine's own `limit`, `offset` and `with`), an unknown `_count` key, and an unread key in a nested write payload.

`count({ distinct })` does not throw: `distinct` is not a `count` key, so it counts every matching row. Rewrite those calls.

## Port module by module

Once the compat client is in place, port one module at a time to the typed `db` exported next to it. Both share one connection pool. For each module:

1. Replace `prisma.` with `db.`, and singular model names with table accessors: `prisma.user` becomes `db.users`.
2. Replace `include:` with `with:`. `take`, `skip`, `cursor` and `distinct` keep their names.
3. Delete any `skip: 1` next to a `cursor`, and audit cursors that had no `skip` (see [Cursor pagination](#cursor-pagination)).
4. Check relation names. Native names come from foreign keys, so a Prisma field called `author` may be `user` natively. The report lists each pair; [`relationNames`](/cli#renaming-derived-relations-relationnames) renames them.
5. Port raw SQL: `prisma.$queryRaw` becomes ``db.raw`...` ``, or ``db.sql<T>`...` `` for typed rows.

The report's "Many-to-many relations (audit these call sites)" section ends with a grep over the Prisma field names. Run it and review every write that nests one of them, because [many-to-many nested writes](/nested-writes#many-to-many-relations) support only `connect`, `disconnect` and `set`.

When nothing imports the compat client, uninstall `prisma` and `@prisma/client` and delete `schema.prisma`.

## API mapping

| Prisma | Turbine | Notes |
|---|---|---|
| `prisma.user.findMany` | `db.users.findMany` | The accessor is the table name in camelCase. |
| `findUnique`, `findFirst`, `findUniqueOrThrow`, `findFirstOrThrow` | Same names | `*OrThrow` throws `NotFoundError` ([E001](/errors#e001)). |
| `create`, `createMany`, `update`, `delete`, `upsert`, `count` | Same names | Same argument shapes. `update` takes `increment`, `decrement`, `multiply`, `divide` and `set`. |
| `updateMany`, `deleteMany` | Same names | An empty `where` throws unless you pass [`allowFullTableScan: UNSAFE`](/global-filters#privilege-options-and-the-unsafe-symbol). |
| `aggregate`, `groupBy` | Same names | `_sum` and `_avg` over `bigint` or `numeric` return exact strings. |
| `include: { posts: true }` | `with: { posts: true }` | The only renamed key. |
| `include: { _count: { select: { posts: true } } }` | `with: { _count: { posts: true } }` | No `select` wrapper. |
| `select`, `omit`, `where`, `orderBy`, `distinct` | Same | All filter operators and relation filters (`some`, `every`, `none`) carry over. |
| `take`, `skip` | Same | Aliases for `limit` and `offset`, at the top level and inside `with`. |
| `cursor: { id: 99 }` | Same shape | Exclusive in Turbine. See below. |
| Nested writes (`create`, `connect`, ...) | Same shape | One transaction. Many-to-many takes only `connect`, `disconnect` and `set`. |
| `prisma.$transaction(async (tx) => ...)` | `db.$transaction(async (tx) => ...)` | Nested calls use savepoints. |
| `prisma.$queryRaw` | ``db.raw`...` `` or ``db.sql<T>`...` `` | Every `${value}` is a bound parameter. |

## Schema translation

To keep an existing database, introspect it with `npx turbine generate` instead of translating the schema by hand. For a new code-first schema, a Prisma model becomes a `defineSchema()` table:

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  posts     Post[]
  createdAt DateTime @default(now())
}

model Post {
  id     Int    @id @default(autoincrement())
  userId Int
  user   User   @relation(fields: [userId], references: [id])
  title  String
}
```

```ts
import { defineSchema } from 'turbine-orm';

export default defineSchema({
  users: {
    id: { type: 'serial', primaryKey: true },
    email: { type: 'text', unique: true, notNull: true },
    createdAt: { type: 'timestamptz', notNull: true, default: 'now()' },
  },
  posts: {
    id: { type: 'serial', primaryKey: true },
    userId: { type: 'integer', notNull: true, references: 'users.id' },
    title: { type: 'text', notNull: true },
  },
});
```

Relations are not declared: Turbine derives them from foreign keys, so `posts.userId` gives `posts.user` and `users.posts`. A foreign key covered by a unique constraint makes a one-to-one, so the parent side gets a singular name and an `object | null` value (`user.profile`), as in Prisma. `turbine generate --legacy-to-many-uniques` keeps the plural array instead. See [Schema](/schema) for every column option.

## Behavior differences to audit

### Values that change shape silently

| Column | Prisma returns | Turbine returns |
|---|---|---|
| `Decimal` / `numeric` | a `Decimal` instance | a `string` |
| `BigInt` / `int8` | a `bigint` | a `number`, or a `string` above `Number.MAX_SAFE_INTEGER` |

Neither throws. `total.plus(x)` breaks loudly, but `Number(total) * qty` quietly goes through floats, and `id > cutoff` compares strings above 2^53. Grep for both before you port a billing or ledger schema.

### Cursor pagination

Turbine's native cursor is **exclusive**: the row the cursor names is not returned, and the page continues from it in the query's `orderBy`.

- Prisma `cursor: { id }` plus `skip: 1` becomes `cursor: { id }`. Drop the `skip`.
- Prisma `cursor: { id }` with no `skip` is inclusive. Ported unchanged, it silently loses the anchor row.
- The cursor must name a unique key. `cursor: { createdAt }` alone throws `ValidationError` ([E003](/errors#e003)).

The compat client keeps Prisma's semantics for every order: the page starts at the cursor row and `skip` counts from there. See [Pagination](/filtering#pagination-limit--take-offset--skip-cursor).

### Other differences

- **Relation arrays have no guaranteed order.** Add `orderBy` to any `with` block your code depends on, or set `stableRelationOrder`.
- **Paginated reads.** The compat client orders a `take`/`skip` page by primary key, as Prisma does. Native `findMany` sends a bare `LIMIT` unless you set [`implicitPkOrdering: true`](/filtering#deterministic-pages-the-unordered-pagination-warning).
- **`time` columns.** The compat client returns a `Date` on 1970-01-01 UTC, as Prisma does. Native reads return the `'09:00:00'` string.
- **SSL in the connection string.** With `sslmode=require`, `pg` prints a `SECURITY WARNING`. Use `sslmode=verify-full`, or `uselibpqcompat=true&sslmode=require` for encryption without certificate verification.

These already match Prisma: `timestamp` and `date` columns read and write as UTC ([details](/schema#zone-less-columns-timestamp-and-date-read-as-utc)), `upsert` looks the row up by `where` when `where` and `create` differ, and a bare to-one relation filter works without `is`.
