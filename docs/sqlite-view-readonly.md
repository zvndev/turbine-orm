SQLite library introspection accepts `includeViews: true` on `introspectSqliteDatabase`, `introspectBetterSqlite3Database`, `introspectSqlite`, and root `introspect` with `sqliteDialect`. It includes ordinary views in the main database; views remain excluded by default. Existing include/exclude filters apply.

Views carry `isView: true` and have no inferred primary or unique keys. Generated keyless view accessors omit `findUnique` and `findUniqueOrThrow`. Write methods remain in the existing types and reject with E003 at runtime, including views with INSTEAD OF triggers. Computed columns keep the unknown types reported by SQLite.

Selecting a JSON view without its base table preserves JSON decoding. A schema-aware client with a JSON view can decode native main-database JSON origins omitted by the public filter, including raw aliases; explicit known-origin schema declarations retain precedence. Bare pools, empty schemas and table-only schemas keep their prior raw JSON-cell behavior. JSON-looking TEXT, computed expressions and attached or temporary origins are not inferred from projected names.

For a SQLite CLI project, `turbine generate --include-views` and `turbine pull --include-views` enable the same discovery. The `init` and `status` commands do not take the flag: run `generate` or `pull` with it after `init`. Discovery opens the existing file read-only and honors the configured include/exclude filters. Without the flag, views stay excluded. This option does not add view DDL, migration management, or materialized views.

Root-view create and update calls carrying caller-declared nested relations reject before transaction checkout or related SQL. Both upsert argument shapes reject with the view-specific E003 before lookup. Inside an already-open caller transaction, the existing savepoint and rollback-to-savepoint lifecycle may run; no data SQL is sent and the caller transaction remains usable. This does not promise validation of every descendant before writing an ordinary table root.

`introspectBetterSqlite3Database(handle, options)` accepts the same include/exclude, includeViews, logger and legacyToManyUniques options as the builtin handle introspector. It keeps the supplied handle open and leaves its transaction and connection settings unchanged. Both drivers produce the same read-only view metadata and runtime write refusals. Views in temporary or attached databases are excluded. Generated code uses the existing identifier validation: a quoted native name that cannot form a TypeScript entity name remains readable through native metadata, but generation rejects it. Use the public `include` filter to select emittable names.
