# MySQL transaction deadline outcomes

MySQL transaction timeouts use the acquired connection's recovery policy. A deadline closes the transaction handle immediately, so a callback that resumes later cannot send more SQL through it. This applies to callback and deferred-array `$transaction` calls. Raw `transaction` has no deadline option, but uses the same cleanup policy on failure or unawaited work.

An idle connection can send ROLLBACK. Only a successful response within the existing cleanup grace establishes confirmed rollback. A transaction deadline then rejects with `TimeoutError` (`TURBINE_E002`) and `outcome: 'not-executed'`.

A statement still running at the deadline cannot be cancelled through mysql2. Turbine discards its checkout and reports `outcome: 'unknown'`, without claiming server cancellation or acknowledged rollback. Server work and locks may remain after public rejection. Do not infer acknowledgement from a closed socket or a rejected JavaScript promise. A discarded connection's session stays on the server until its statement finishes, so under timeouts MySQL can briefly show more sessions than the pool's connection limit. A dispatched COMMIT that gets no server answer raises E021 with the hiding failure as `cause`. A later ROLLBACK cannot establish whether it committed.

Unrelated callback and driver failures retain their original rejection identity, including `undefined`, null, false, zero and empty string. Unknown cleanup uses the existing `transaction-outcome-unknown` log code. Successful transactions retain their original SQL sequence and output. Caller pool settings and lifecycle remain the caller's.

The native fixture is `src/test/fixtures/mysql-timeout/native.mjs`. It requires a disposable owned MySQL database in `MYSQL_URL`, an actual installed package directory in `CONSUMER`, `FORMAT=esm|cjs`, and a fresh `REPORT` path. `EXPECT_RECOVERY=1` also requires the actual generated client compiled under `<CONSUMER>/<FORMAT>/compiled/generated/index.js`. The fixture creates its own `lifecycle_items` table. It checks idle and blocked deadlines, full late callback refusal, falsy reasons, exact rows and reselect results, caller reuse, and recovery faults. The fault controls reject before ROLLBACK dispatch, hide an actual COMMIT acknowledgement from the ORM, or hold an actual ROLLBACK response past the cleanup grace. These are explicit driver-boundary injections, not claims of a network interruption.

Qualification covers MySQL 8.4.0 with mysql2 3.24.6, Node 22.16.0 and 24.10.0, installed ESM/CJS and generated strict consumers in ordinary and NO_BACKSLASH_ESCAPES server modes. It does not certify the server or driver floors, hosted providers, ordinary-query cancellation, or external callback effects. The package's source driver pins remain distinct from that installed tuple.
