# Optional better-sqlite3 package build

Unpublished `turbine-orm-better-sqlite3-runtime-stage` is a
private runtime subset. Install the tarball under the actual alias
`npm install turbine-orm@file:/absolute/path/ARCHIVE.tgz`.

Exports are exactly `turbine-orm`, `turbine-orm/better-sqlite3`, and
`turbine-orm/sql`. Root values are the existing better-sqlite3 factory,
dialect and introspection, public errors, `defineSchema`, and
`schemaDefToMetadata`. Original type-only root declarations support generated
clients. There is no CLI, generator, seed, PG factory or builtin SQLite value
export. Generate in a separate full tooling installation.

The mandatory driver is exactly `better-sqlite3@12.11.1`. The unchanged
package-local factory resolves this dependency even when the application has
a conflicting peer. Supplied handles remain caller-owned. Factory-owned
handles retain FULL synchronous durability, and the adapter preserves its
existing named binding, decoding, transaction, iterator and RETURNING
contracts. Native migration/session APIs are unavailable through this adapter.

The optional pg peer records an existing shared internal loader input. It
grants no PG capability. Production installs need no PG-family, Miniflare,
workerd or compiler package. The default package still has mandatory pg.

Staging performs the complete normal clean build. Verification reconstructs
the complete runtime, declaration and literal lazy graph from the pinned
normal archive and fixed facade. Only existing PG import transformations are
applied to original emissions. Both opaque helper copies and their exact
literal better-sqlite3 callers are byte-pinned, with complete normal source
and emission bindings. Source/tool/template/build freshness checks remain
mandatory. Changed inputs refuse until explicitly requalified. This finite
exception allows no arbitrary dynamic loader or missing target.

Native qualification is bounded to exact Node22.16.0 and24.10.0, in ESM and
CJS. It is no builtin SQLite parity, broad runtime support, release or timing
claim. Installed native dependency closure is measured separately from the
runtime tarball and the full generation tools.

The runtime package version is read from the root package.json and suffixed with `-runtime.0`.
