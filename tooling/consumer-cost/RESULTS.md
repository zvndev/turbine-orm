# Recorded packed consumer campaign

All eight packed profiles completed, including three separate optional-entry
behavior checks and three strict public-entry type consumers. The definitive
serial 100/500/1000-table generated PostgreSQL consumers all compiled with exit
0 and no compiler errors. These are single-host observations, with no performance
ranking or CI threshold.

## Candidate and reproduction

Candidate: turbine-orm 0.93.1, built from source commit
`9cf60050bb8ea2472f91eb28f0e78bc59bad49b8` and packed with lifecycle scripts
disabled. Packed SHA-256:
`652ba112b554e482ad8132ec274ffe56b5038222980fff66c757a64cb76f0c7c`.
The source reference is a caller assertion; tarball identity is authoritative.
The tarball retains its development prepare declaration; install scripts were
disabled for every consumer.

Executed 2026-11-06 UTC on Node v26.12.0, npm 11.20.0,
Linux x64; consumer TypeScript 6.0.3 and
@types/node 22.20.4. The existing profile pins remain pg 8.22.0 and mysql2 3.24.5.
The candidate's ranged mandatory pg resolved to **8.23.1** in the new optional
profiles' immutable locks; it was not replaced, omitted or externalized from
installation accounting. PostgreSQL/serverless profiles retain pinned pg 8.22.0.
Every new profile installed 15 production package instances including the
candidate, pg and its complete installed production closure. Neither optional
mysql2 nor mssql was installed for the seed profiles.

Follow the [README commands](./README.md#run) with this exact candidate and
prepared locks. Smoke used all eight profiles, size 5, two fresh-process runtime
samples and a 120000 ms command timeout. Scale used only postgres, sizes
100,500,1000 in that order, three separate runtime samples, a 180000 ms timeout
per command and a 4096 MiB V8 old-space bound per compiler. Only the three
compiler cases measure generated type scale; runtime samples are separate.
No compiler owned by this run overlapped another compiler in the definitive
scale campaign. Other host work and filesystem caches were uncontrolled.

## Strict generated consumers

Every table has eight columns and two ring relations; every accessor is queried
with nested relation/type assertions. Each run uses the actual packed public
generator, strict true, skipLibCheck false, noEmit true and incremental false.
All three generated files are counted in generated bytes. Consumer bytes exclude
them. The synthetic workload tests compiler scaling, not SQL execution or
runtime engine performance.

A separate deliberate 16 MiB compiler old-space control on two tables aborted
with the actual fatal V8 heap diagnostic (SIGABRT). Its case is
resource-exhausted, its campaign fails, and final in-process resource metrics
are unavailable. Full generated inputs, stderr and externally observed samples
were retained. A signal alone is never classified as OOM. An earlier successful
attempt overlapped that short control and was retained separately; the table
above uses the later serial attempt. Earlier reports missing CPU fields were
also retained; the monitor now uses Node's actual CPU resource field names.

## Validation and evidence identity

Behavioral controls passed 5 tests, zero failures/skips, independently on Node
26.12.0 and Node 22.16.0. They include real strict compiler errors, real heap
exhaustion/stale-resource refusal, broken packed public imports, defective SQL
binding, eager seed callbacks, absent seed validation and altered lock hashes.
Build, scoped Biome and syntax/diff checks passed. No native database service
was started. Successful temporary consumers were removed automatically; failure
consumer cleanup is recorded alongside retained evidence.
